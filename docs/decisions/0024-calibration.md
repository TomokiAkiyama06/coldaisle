## 1. Context

DS18B20 も AM2320 も確度は ±0.5℃。**ΔT には最悪 ±1.0℃ の系統誤差**が乗る
（spec-review W-02）。再循環の判定は数℃の話なので無視できない。

改善するのは**センサー間の相対精度**であって絶対精度ではない。
本システムが判断に使うのは温度差なので、それで足りる。

---

## 2. Decision

### 2.1 読み取り元は **DB。シリアルを開かない**

**シリアルポートを開いてよいのは取り込みデーモンだけ**（AGENTS.md ルール6）。
較正コマンドが2本目の読み手になると、どちらが取りこぼしたのか分からなくなる。

デーモンを動かしたまま放置し、**保存済みの区間から計算する。**
副産物として、較正に使った区間は DB に残り、あとから検証できる。

### 2.2 基準は**全センサーの平均**

spec-review W-02 のとおり。「正しい温度計」を持たない前提で、
**互いを基準にする。** 絶対精度は改善しないが、必要なのは相対値である。

オフセットは**センサーの読みへ足して基準へ寄せる向き**にする
（`Normalizer` が加算する）。合計は 0 になる。

### 2.3 **同じ空気に置かれていないなら較正しない**

センサー間のばらつきが 2.0℃ を超えたら受け付けない。

超えたまま較正すると、**本物の温度勾配をオフセットとして焼き付ける。**
以降その勾配は見えなくなり、**再循環そのものが検出できなくなる**
（`d.intake_rise` は前面吸気と室温の差である）。

これがこの機能で最も危険な失敗なので、既定で止める。`--force` は残すが勧めない。

同じ理由で、**測定が少ないチャネル**（既定 120 件未満）と
**測定が無いチャネル**があっても受け付けない。残りだけの平均は基準にならない。

### 2.4 **黙って書き換えない**

較正値は**以降のすべての測定の解釈を変える。** 既定では計算結果を見せるだけで、
`--apply` を付けたときだけ書く（`coldaisle-memory` と同じ作法。0020 §2.2）。

書いたら**取り込みの再起動が要る**（較正値は起動時に読む）ことを出力に書く。

### 2.5 **2回目の較正は前回に足す**

`Normalizer` は**保存する前に**オフセットを足している（0007）。したがって DB から
読んだ平均は**既に補正済み**で、ここで出るのは**残差**である。

置き換えると、2回目の較正で前回の補正が消える。**6ヶ月ごとのやり直しが、
毎回の初期化になり、個体差が黙って戻る。**

```text
前回 +0.190 → 今回 +0.190（残差 +0.000）   ← 足す（正しい）
前回 +0.190 → 今回 +0.000（残差 +0.000）   ← 置き換え（個体差が戻る）
```

生の値から計算する案は採れない。**保存しているのは補正後の値だけ**である
（生値も持つと、どちらが本物かが曖昧になる）。

出力には**前後の両方を出す。** 置き換えか加算かを人が確かめられるようにする。

### 2.6 記録に**根拠を残す**

| 項目 | なぜ要るか |
|---|---|
| `calibrated_at` | いつの較正か。これが無いと古さを判定できない |
| `reference` | 何を基準にしたか（`mean_of_all`） |
| `samples` | 何件で測ったか。少ない標本の較正を後から見分けられる |

**有効期限は記録ではなく方針に置く**（次節）。

引き継いだ `note` は**書き換える。** 較正**前**について書かれた覚書
（「実測前の暫定値で、全チャネル 0.0」）をそのまま残すと、
**ファイルが自分自身と食い違う。**

### 2.7 **記録と方針を別のファイルにする**

| ファイル | 誰が書くか | 中身 |
|---|---|---|
| `config/calibration.json` | **道具**（`coldaisle-calibrate`） | 較正の**記録**。オフセットと根拠 |
| `config/calibration.yaml` | **人** | 較正の**方針**。上限・最低件数・有効期限・窓の長さ |

閾値を設定から読むのは AGENTS.md ルール9 のとおりだが、**記録の側に混ぜては
いけない。** 道具が記録を書き直すたびに、人が決めた設定を上書きすることになる。

（最初は `revalidate_after_days` を記録の側に置いていた。道具が書き換える
ファイルに人の設定を置くのは筋が悪い。）

### 2.8 未較正は**期限切れとして扱う**

`calibrated_at` が `null` なら、デーモンは起動のたびに警告する。
出荷時の `config/calibration.json` は全チャネル 0.0 / 未較正である。

**較正済みのつもりで生値を見ることにならない**ようにする。
センサーは経年でずれるので、**ずれたオフセットは測っていないより悪い。**

時刻にオフセットが無い（`2026-09-10T11:00:00`）場合も期限切れ扱いにする。
解釈が割れる値を**推測しない。**

## 3. Consequences

### 良くなること

- ΔT の系統誤差が ±1.0℃ から ±0.15℃ 程度へ（#13 の受入基準）
- 較正の根拠が記録に残り、`coldaisle-memory` が変更を拾う（0020）
- **同じ空気に置いていない較正が止まる**（2.3）
- 古い較正・未較正が起動時に分かる（2.8）
- **やり直しても前回の補正が消えない**（2.5）

### 悪くなること・その緩和

| トレードオフ | 緩和策 |
|---|---|
| 較正にデーモンの稼働が要る | 常時動かす前提の系なので、追加の手間はほぼ無い |
| 物理的な準備（30分の熱平衡）が要る | 手順を `docs/calibration.md` に書いた。省くと待ち時間の差がオフセットになる |
| 絶対精度は改善しない | 判断に使うのは温度差。絶対値が要る用途は無い |
| `--force` があると押し切られうる | 既定では止まり、理由を書く。押し切ったことは `forced` としてログに残る |

## 4. 却下した代替案

| 案 | 却下理由 |
|---|---|
| 較正コマンドがシリアルを直接読む | 開いてよいのはデーモンだけ（2.1）。2本目の読み手は取りこぼしの原因を曖昧にする |
| 特定の1本を基準にする | その1本のずれが全体に乗る。**「正しい温度計」を持っていない**（2.2） |
| ばらつきが大きくても計算だけして書く | 本物の勾配を焼き付け、再循環が見えなくなる（2.3） |
| 計算したら自動で書き込む | 以降のすべての測定の解釈が変わる。人が見てから（2.4） |
| `note` を引き継ぐ | 較正前について書かれた覚書がファイル内で矛盾する（2.5） |
| 未較正を「オフセット 0 で較正済み」とみなす | 較正済みのつもりで生値を見ることになる（2.6） |
| 残差で置き換える | 2回目の較正で前回の補正が消え、個体差が黙って戻る（2.5） |
| 生の値も保存して、そこから計算する | どちらが本物かが曖昧になる（2.5） |
| 閾値をコードの定数にする | AGENTS.md ルール9。設定から読む（2.7） |
| 方針を `calibration.json` に混ぜる | 道具が書き直すたびに人の設定を上書きする（2.7） |
