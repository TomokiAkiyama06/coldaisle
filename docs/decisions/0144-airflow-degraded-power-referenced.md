## 1. Context

### 1.1 今の判定と T1 の発火

`airflow_degraded`（FR-406）は `d.gpu_delta`（`air.gpu_exhaust` − `air.gpu_intake`）が 20 °C を超えた状態が 300 s 続くと
warning で発火する（解除 18 °C）。値は FR-406 の暫定値のまま、GPU の電力を見ていない。

2026-10-15 の T1 の間に 17:28・17:38・18:01 の 3 回発火した。`d.gpu_delta` は 26〜30 °C だった。
これは故障ではない。GPU 600 W では、BIOS・fand のどちらでも排気が吸気より約 30 °C 高い（下の 1.2）。
今の閾値では GPU を使うたびに鳴り、通知が意味を失う。

所有者の判断（2026-10-15、#326）: GPU の電力と合わせて判定する（同じ電力のときに、いつもより差が大きいときだけ鳴らす）。

### 1.2 材料の数字

2026-10-13〜15 の試験の書き出し（所有者の機械。生データはリポジトリに置かない）から、`power.gpu.0` が ±5 % の範囲に
8 分以上とどまった区間の `d.gpu_delta` を集めた。T4・T5・T7 の試行ごとの値は、負荷を止める直前の 2 分の平均である。
吸気（`air.gpu_intake`）はどれも 19.6〜23.8 °C。

| GPU 電力 | GPU の Fan | 出どころ | 定常の `d.gpu_delta`（試行ごとの平均） | ばらつき（試行内の標準偏差・全体の範囲） |
|---|---|---|---|---|
| アイドル（6〜7 W） | 30 %（曲線の最低） | T7 の各試行の前（4 回）ほか | 3.3〜4.2 | ≤ 0.25・2.6〜5.0 |
| 300 W | GPU 自身の既定の制御 | T4 の測り直し・T5 (ii)（2 回） | 26.1〜26.2 | ≤ 0.10・25.9〜26.3 |
| 450 W | GPU 自身の既定の制御 | T5 (ii)・(iii)（2 回） | 33.4〜33.6 | ≤ 0.13・33.3〜33.8 |
| 600 W | 0130 の曲線（68〜73 %） | T7 の 4 試行・T5 の 0130 のやり直し（2 回） | 30.4〜32.0 | ≤ 0.25・30.1〜32.6 |
| 600 W | 0128 の曲線（100 %） | T5 の 0128 のやり直し・GPU の Fan のサービスの確認 | 23.6〜23.9 | ≤ 0.15・22.9〜24.0 |
| 600 W | 固定 80 % | GPU の Fan の固定の測定（2026-10-14） | 27.5 | 0.22・27.1〜27.9 |

| 600 W | 固定 60 % | 同 | 36.0 | 0.14・35.7〜36.2 |

- 試行内のばらつきは小さく（標準偏差 0.25 °C 以下）、同じ電力・同じ GPU の Fan の試行の間の差も 1.6 °C 以内だった
- 600 W では、`d.gpu_delta` × GPU の Fan（%）がほぼ一定（固定の 3 点で 2160〜2210、0130 の曲線で 2160〜2190、100 % で 2370）。
  差は GPU の Fan が送る風量にほぼ反比例する。既定の制御の 47 % の推定（46〜50 °C）はこの関係から出した
- 300 W・450 W の値は、どれも GPU の Fan のサービス（0128）の前の、既定の制御の下のもの。今の 0130 の曲線は、既定の制御
  （64 °C で 36 %・79 °C で 47 %。0128 §1）よりどの温度でも高く回るので、同じ電力の今の値はこれ以下と見込む
- アイドルの値の最大（5.0 °C）は T7 のアイドルの試行の前のもの。高い負荷の直後の余熱（下）を含めると 8 °C 台まで出る
- 600 W の負荷を止めた後の減り方（T7 の 3 回）: 10 °C 未満まで 235〜255 s、8 °C 未満まで 282〜308 s、6 °C 未満まで 340〜380 s。
  負荷を始めた直後は、排気が遅れて上がるので差は定常より小さい

### 1.3 差だけでは区別できないこと

- 300 W の正常（26 °C）と 600 W の正常（30〜32 °C）は、20 °C を超える。600 W の正常と、600 W で GPU の Fan が 60 % まで
  落ちた状態（36 °C）の差は 4 °C しかない。電力を見ずに一つの閾値で分けることはできない
- 差 ÷ 電力（°C/W）は、アイドル（3〜5 °C ÷ 6〜7 W = 0.5〜0.8）で大きく、600 W（0.05）の 10 倍以上になる。
  低い電力ほど誤って鳴りやすく、閾値を一つに決められない

## 2. Decision

### 2.1 判定の形（期待値からの超過）

`airflow_degraded` を「**GPU の電力から求めた、正常な `d.gpu_delta` の上限（期待値）を超えた分**」で判定する。

```text
超過 = d.gpu_delta − 期待値(参照電力)
発火: 超過 > threshold の状態が fire_after_s 続く
解除: 超過 < clear（ヒステリシス。0012 §2.5）
```

- **期待値**は `config/rules.yaml` の点の表（GPU 電力 W → 正常の上限 °C）を線形に補う。表の外は端の値。
  表の値は**電力について減らない**（読み込み時に検査する。2.2）
- **参照電力**は `power.gpu.0` の直近 `power_window_s` の最大（2.3）
- 状態機械（pending → firing → resolved）・`fire_after_s` の数え方・発火の前の揺らぎの行を消すことは 0012 のまま
- 評価の時刻と入口は今のまま（取り込みの `Engine.on_sample()`。基板のサンプルごと）。`power.gpu.0` は取り込みのサンプルに載らず、
  `coldaisle-telemetry` が DB へ書くので、0131 §2.3 と同じく**評価時刻で DB を読む**（`latest(at_ms=評価時刻)` と `stats()`）

### 2.2 値（`provisional`）

| 項目 | 値 | 根拠 |
|---|---|---|
| 期待値の点 0 W | 5.0 °C | アイドルの最大 5.0（1.2） |
| 期待値の点 300 W | 26.5 °C | 300 W の最大 26.3 |
| 期待値の点 450 W | 34.0 °C | 450 W の最大 33.8 |
| 期待値の点 600 W | 34.0 °C | 600 W（0130 の曲線）の最大は 32.6。表を減らさないため 450 W と同じにする |
| `threshold`（超過の発火） | 6.0 °C | 下の表。正常の最大から 6 °C 以上の余裕 |
| `clear`（超過の解除） | 4.0 °C | 発火の内側（0012 §2.5） |
| `fire_after_s` | 300 s | 今のまま（FR-406 の 5 分） |
| `power_window_s` | 600 s | 2.3 |

発火する `d.gpu_delta` は、参照電力ごとに次になる（期待値 + 6.0）。

| 参照電力 | 発火する `d.gpu_delta` | 正常の最大（1.2）との差 | 鳴る・鳴らない（材料の数字） |
|---|---|---|---|
| アイドル（0〜7 W） | 11.0〜11.5 °C 超 | +6.0（最大 5.0） | 鳴らない（アイドルの定常 2.6〜5.0） |
| 300 W | 32.5 °C 超 | +6.2（最大 26.3） | 鳴らない（26.1〜26.2） |
| 450 W | 40.0 °C 超 | +6.2（最大 33.8） | 鳴らない（33.4〜33.6） |
| 600 W | 40.0 °C 超 | +7.4（最大 32.6） | **定常は鳴らない**（0130 の曲線 30.4〜32.0・100 % 23.6〜23.9・固定 70〜80 % 27.5〜31.6）。固定 60 %（36.0）も鳴らない |
| 600 W・GPU の Fan が既定の制御（約 47 %） | 40.0 °C 超 | — | **鳴る**（推定 46〜50 °C、超過 12〜16 °C） |
| 電力が分からない（2.4） | 40.0 °C 超 | — | 600 W と同じ |

- 600 W で鳴るのは、`d.gpu_delta` × GPU の Fan ≈ 2160〜2370（1.2）から、GPU の Fan がおよそ **54〜59 % 以下**に相当する風量のとき。
  筐体の Fan・フィルタ・吸気の塞がりで同じだけ風量が落ちたときも同じく鳴る
- T1 で鳴った 26〜30 °C は、参照電力が 300 W 以上ならどの電力でも閾値（32.5 °C 以上）に届かない
- 値の確定は T1 の記録で行う（§5 の 1）

### 2.3 電力の変化の直後（参照電力は直近 600 s の最大）

- **上げの直後**: 参照電力は新しい電力にすぐ上がり、期待値も上がる。差は排気の遅れで定常より小さいので、誤って鳴らない
- **下げの直後**: 差は数分かけて減る（600 W から 6 °C 未満まで 340〜380 s。1.2）。参照電力に今の電力を使うと、
  アイドルの期待値（5 °C）と余熱の残った差（数分は 10 °C 以上）を比べて誤って発火の待ちに入る。
  **直近 `power_window_s`（600 s）の最大を参照電力にする**ことで、下げてから 600 s は下げる前の期待値と比べる。
  600 s は、材料の最も遅い減り（6 °C 未満まで 380 s）の約 1.6 倍
- 代わりに、電力を下げてから 600 s の間は、下げた後の電力に対しては鈍い（下げる前の電力の期待値で判定する）

### 2.4 `power.gpu.0` が無い・stale のとき（0139 との整合）

- `power.gpu.0` の最新値が無い・ok でない（stale を含む。閾値は `config/quality.yaml` の `stale_after_ms` に一本化。0131 §2.3）ときは、
  **参照電力を「分からない」とし、期待値に表の最大（34.0 °C）を使う**。発火する差は 600 W と同じ 40.0 °C になる
- このときもルールは評価を続ける（黙らない）。電力が分からないことで、誤って鳴ることも、発火の待ちを取り消すこともない。
  発火の待ちの間に電力が分からなくなったら、その周期から最大の期待値で比べ、超過が `clear` を下回れば 0012 のとおり行を消す
- 直近の窓の最大は、最新値が ok のときだけ使う（窓の中の古い ok の値で、止まった収集の後の電力を推測しない）
- **0139 は変えない。** `airflow_degraded` は 0139 の 5 つのルール（`GAP_RESET_RULES`）に残り、入力の欠け（`air.gpu_exhaust`・
  `air.gpu_intake` の `SENSOR_MISSING`、`SENSOR_FAULT`）で発火の待ちを取り消す扱いはそのまま。`d.gpu_delta` が計算できない周期は
  今のとおり何も言わない（0012 §2.8）。`power.gpu.0` は 0139 の「入力」に含めない（欠けても上のとおり評価を続けるので、
  空白をまたいで継続を数える問題（0139 §1.2）が起きない）
- 通知の文（`detail`）には、比べた期待値と参照電力、または電力が分からなかったことを書く

### 2.5 低い電力

- 期待値の表で扱い、特別の下限（この電力未満では評価しない）を持たない。アイドルで鳴るのは差が 11 °C を超えて 300 s 続いたとき
  だけで、正常のアイドル（2.6〜5.0 °C）と 600 W を下げた後の余熱（2.3 で窓の中）から離れている
- 差 ÷ 電力のように電力で割らないので、低い電力で値が跳ねない
- 100〜250 W の定常の材料は無い。表は 0 W と 300 W の間を線形に補う。GPU の Fan は電力とともに上がるので、
  差は電力に対して上に凸にはならず、線形の補いは上限として安全側と見込む（§5 の 2 で T1 の記録と照らす）

### 2.6 実装の形

- `config/rules.yaml` の `airflow_degraded` を次の形にする（値をコードに書かない。AGENTS.md ルール 9）

```yaml
airflow_degraded:
  enabled: true
  severity: warning
  metric: d.gpu_delta
  power_metric: power.gpu.0
  power_window_s: 600.0
  expected:            # GPU 電力（W）→ 正常の d.gpu_delta の上限（°C）
    - {power_w: 0.0, value: 5.0}
    - {power_w: 300.0, value: 26.5}
    - {power_w: 450.0, value: 34.0}
    - {power_w: 600.0, value: 34.0}
  threshold: 6.0       # 期待値を超えた分（°C）
  clear: 4.0
  fire_after_s: 300.0
```

- 新しいルールの型（`PowerReferencedRule`）。読み込み時に、点が 2 つ以上・`power_w` が増える・`value` が減らない・
  `clear < threshold`・`power_window_s > 0` を検査し、外れたら起動を止める（0012 §2.9 と同じく、設定の誤りを静かに通さない）。
  `power_metric` も未知のメトリクスの検査（0012 §2.9）にかける
- アラートの行の `threshold` には**その時の発火の `d.gpu_delta`**（期待値 + `threshold`）、`trigger_value` には `d.gpu_delta` を入れる。
  「メトリクスの値と閾値」を読む今の通知・説明（0016）の意味を変えないため
- `config/metrics.yaml` は変えない（`d.gpu_delta` と `power.gpu.0` は既にある）

### 2.7 テストで確かめること（実機なし。SimulatedClock と 2.5 s のサンプル列。AGENTS.md ルール 7）

材料の要約の数字（1.2）で合成したサンプル列で次を確かめる。

1. 600 W（`d.gpu_delta` 32.6）・450 W（33.8）・300 W（26.3）・アイドル（5.0）の定常は、`fire_after_s` を十分に越えても発火しない
2. 600 W で `d.gpu_delta` 47 °C（既定の制御の推定）が 300 s 続くと発火し、32 °C に戻ると解除する
3. 600 W から アイドルへ下げ、差が 1.2 の減り方（380 s で 6 °C 未満）で減るときに発火しない
4. `power.gpu.0` が無い・stale のときは、差 36 °C では発火せず、47 °C では発火する
5. 0139 の取り消し（`air.gpu_exhaust` の `SENSOR_MISSING` が発火中）は今のまま働く
6. 設定の誤り（減る表・`clear >= threshold`・点が 1 つ）を読み込みで落とす

## 3. Consequences

### 良くなること

- GPU を使うたびに `AIRFLOW_DEGRADED` が鳴らない。300〜600 W の正常な定常から 6 °C 以上離れたときだけ鳴る
- 「同じ電力のときにいつもより差が大きい」という FR-406 の意図（風量の低下）に近い判定になる
- 電力が分からないときも、600 W の基準で評価を続ける（黙らない）

### 悪くなること・その緩和

- **GPU の Fan が既定の制御に戻っただけでは、450 W 以下では鳴らない**（期待値の 300 W・450 W の点が既定の制御の下の値のため）。
  緩和: それは `GPU_FAN_NOT_MANUAL`（0131）が温度に関係なく 30 s で捉え、600 W では `GPU_FAN_BELOW_CURVE`（0140）も捉える。
  T1 の記録で 0130 の曲線の下の 300 W・450 W の値が分かれば、表を下げられる（§5 の 1）
- 電力を下げてから 600 s は、下げた後の電力に対しては鈍い（2.3）
- 寒い部屋では GPU コアが下がり、0130 の曲線の GPU の Fan が下がるので、600 W の差は上がる。材料の吸気は 19.6〜23.8 °C だけで、
  1.2 の関係から粗く見積もると、吸気 15 °C で約 37 °C、10 °C で約 41 °C になり、10 °C 前後では鳴りうる。
  緩和: その室温は運用の想定の外。吸気の低い記録が取れたら照らす（§5 の 3）
- 発火を判断するたびに DB を 2 回読む（最新値と窓の統計。基板のサンプルごと、2.5 s に 1 回）。`rapid_rise` と GPU の Fan のルールも
  同じ読み方をしており、取り込みの周期に比べて小さい

## 4. 却下した代替案

| 案 | 却下の理由 |
|---|---|
| 閾値を上げるだけ（例: 40 °C） | 300 W の正常（26 °C）に対して 14 °C も鈍くなる。450 W 以下の風量の低下はほぼ鳴らない。600 W の正常と GPU の Fan 60 % の差が 4 °C しかなく（1.3）、電力を見ずに決めた値はどの電力にも合わない |
| ルールを止める（`enabled: false`） | 風量の低下（FR-406）を知る手段が無くなる。0130 の曲線の GPU の Fan の故障・筐体の Fan・吸気の塞がりは、GPU の Fan のルール（0131・0140）では捉えられない |
| 差 ÷ 電力（°C/W）に閾値 | 低い電力で値が大きく跳ねる（アイドル 0.5〜0.8・600 W 0.05。1.3）。閾値が一つに決まらず、低い電力の下限を別に足すことになる |
| 今の電力をそのまま参照電力にする | 下げた直後の余熱で誤って発火の待ちに入る（2.3） |
| 電力が分からないときは評価しない（0131 §2.3 のように発火の待ちを取り消す） | `coldaisle-telemetry` が止まると黙って鳴らなくなる。最大の期待値で評価を続けても誤って鳴ることはない（2.4） |
| GPU の Fan の回転（`gpu.0.fan_speed`）も期待値に入れる | 既定の制御に戻った・回らない GPU の Fan を「正常」として期待値を上げてしまい、捉えたい状態を隠す。`gpu.*.fan_speed` は LLM へ渡さないメトリクス（0138）で、ルールの入力に足すと除外の扱いが広がる |
| 吸気の温度も期待値に入れる | 材料の吸気の幅（19.6〜23.8 °C）が狭く、係数を決められない（§5 の 3） |

## 5. 未決事項と仕様に無い判断

### 5.1 仕様（FR-406・#326）に無く、本記録で決めた判断（所有者の承認を求める）

| # | 判断 | 理由 |

| B | 表は電力について減らない（600 W の点を 450 W と同じ 34.0 °C にする） | 450 W の点は既定の制御の値で、今の曲線の 600 W より高い。減る表は「電力が上がると正常の上限が下がる」ことになり、補いの区間で根拠が無い |
| C | 参照電力は直近 600 s の最大 | 2.3 |
| D | `power.gpu.0` が無い・stale では、表の最大を期待値にして評価を続ける（取り消さない・黙らない） | 2.4 |
