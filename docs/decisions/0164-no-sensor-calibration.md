# 決定記録 0164: 空気のセンサーの較正を行わない（offset 0.0 のまま運用する）

- **種別**: Decision Record

- **Date**: 2026-10-22
- **Supersedes**: [`0024`](0024-calibration.md) の §5 の 1「実機での較正」と §5 の 4「ベースライン測定より較正が先」のみ（0024 の仕組みと他の節は有効）

## 1. Context

0024 は較正の仕組み（`coldaisle-calibrate`・`config/calibration.json` の記録・`config/calibration.yaml` の方針・
期限切れの警告）を決め、実機での較正（受入基準: 較正後のばらつき ±0.15 °C 以内）を人の作業として残した（0024 §5 の 1）。
#45 はその作業だけが残っている。

2026-10-22 の時点で、導入先の `config/calibration.json` は出荷のまま全チャネル 0.0・`calibrated_at` は null で、
DB の `calibration_activations` は 2026-10-11 の 1 行（全チャネル 0.0）だけである。
所有者は較正を行わない方針を選んだ。

## 2. Decision

### 2.1 較正を行わない

- 空気のセンサー（DS18B20 ×5・AM2320）の offset は **0.0 のまま運用する**。`coldaisle-calibrate --apply` は実行しない。
- #45 の受入基準（較正後のばらつき ±0.15 °C 以内）は追わない。#45 は not planned で閉じる。
- 0024 の仕組み（CLI・記録と方針の分離・期限切れの警告・`PROBE_CHANGED`）は**そのまま残す**。
  取り込みの起動のたびに出る「未較正（期限切れ扱い）」の警告（0024 §2.8）も消さない。
  較正していないことを隠さないのが 0024 §2.8 の趣旨で、方針で較正しないことと矛盾しない。

### 2.2 温度差の値は ±1.0 °C の系統誤差を持つ前提で扱う

- 各プローブの確度は ±0.5 °C で、**両辺が本記録の空気のプローブ（`air.*`）である温度差**には最悪 **±1.0 °C** の系統誤差が乗る（W-02）。
  対象は `config/metrics.yaml` の `d.intake_rise` / `d.gpu_preheat` / `d.gpu_delta` / `d.top_rise` / `d.rear_rise` / `d.case_delta`。
- 片辺だけが空気のプローブの差（例: `d.connector_rise` = `board.connector_12v2x6` − `air.room`）や、空気のプローブを含まない差
  （例: `d.gpu_internal_delta`）には本記録の ±1.0 °C を当てない。それらの誤差は相手のセンサーの確度から、その閾値の記録で決める
  （片辺の `air.*` が較正されていないことによる ±0.5 °C はそこに含める）。
- 温度差に閾値を置くとき（例: `d.intake_rise` の 5.0 / 4.0、#50 の閾値の確定）は、この誤差を前提に決める。
  閾値と誤差の幅が近く、誤報や見逃しが判断を左右する規則が出てきたら、その記録で較正の要否を改めて決める（§2.4）。
- 制御への影響:
  - Reactive Guard の `intake_rise`（`d.intake_rise`、Front / Rear の floor を**上げるだけ**）は差の値を使うので、
    この誤差がそのまま乗る。誤差は発火の早さ・遅さとして現れ、Guard が Demand を下げる向きには働かない。
    Guard の閾値（`intake_rise_c`）を確定するときは、この誤差を前提にする。
  - Critical Safety が空気の温度（`air.*`）に当てる絶対温度の上限は、較正で絶対精度が変わらない（docs/calibration.md の冒頭）ので、
    較正しないことの影響を受けない。
  - 空気の温度差を新たに安全・制御の閾値に使う規則を足すときは、この誤差をその記録で扱う。

### 2.3 他の記録との関係

- **0153（風量の測定）**: 応答の行列は「区間の開始の時点で有効な `calibration_activations` の行」を要し、
  区間の中で較正を変えないことを求める（§2.9）。offset 0.0 の行（2026-10-11）が有効で、以後変えないので、条件は満たされる。
- **0096 / 0099（較正の digest と変更の記録）**: offset 0.0 の digest のまま変わらない。Dataset v2・学習・
  Workload Hint の証明書の較正の部品も同じ digest を束ねる。
- **#47**（24 時間連続運転）の #45 への依存は外れる（`ISSUES.md` の待ち列からも #45 を外す）。
- **0024 §5 の 4**（ベースライン測定 #50 より較正が先）: 較正を行わないので、#50 は較正を待たない。#50 の閾値は §2.2 の誤差を前提に決める。
- **運用の文書**: `docs/calibration.md` の冒頭と §4（`--apply`）、`config/rules.yaml` の `probe_changed` の hint、`config/calibration.json` の `note`、ダッシュボードのセンサー構成の注記（`src/coldaisle/web/index.html`）に本記録を示し、
  未較正の警告や `PROBE_CHANGED` に応じて `--apply` を実行しないようにする。`docs/requirements.md` の R-02 の対策と M2 の内容も本記録に合わせる。

### 2.4 見直す条件

次のどれかが起きたら、新しい記録で較正を行うかを決める。

1. 温度差の閾値が ±1.0 °C の誤差の幅と近く、その規則の判定が誤差で変わりうる（#50 の閾値の確定のときに確かめる）。
2. 再循環の判定（`d.intake_rise`）などで、誤差で説明できる誤報・見逃しが続く。
3. プローブを差し替え、`PROBE_CHANGED` を受け入れる必要が出た（受け入れの経路は `--apply` だけ。docs/calibration.md §0）。
4. 空気の温度差を安全・制御の閾値に使う規則を足す、または Guard の `intake_rise_c` が誤差の幅と近い値になる（§2.2）。

## 3. Consequences

### 良くなること

- 人の作業（30 分以上の静置と 10 分の記録・プローブの付け外し）が要らない。
- 較正が変わらないので、0153 の応答の行列・Dataset・証明書の較正の束縛が途中で外れない。

### 悪くなること

- 温度差に最悪 ±1.0 °C の系統誤差が残る（空気のプローブどうしの差）。緩和: 閾値の記録で誤差を前提にする（§2.2）、見直す条件を置く（§2.4）。
- 取り込みの起動のたびに未較正の警告が出続ける。緩和: 意図した状態であることを本記録で示す。

## 4. 却下した代替案

- **較正を行う（0024 §5 の 1 のとおり）**: 所有者が行わない方針を選んだ。
- **未較正の警告を止める**: 較正していないことが見えなくなる。0024 §2.8 の趣旨に反する。

なし。
