## 1. Context

本リポジトリは public である。**一度 push した情報は履歴に残り、
force push でも完全には消えない。**

`detect-secrets` は既に pre-commit と CI に入っている（#1）。
しかし Issue #41 が挙げているものの半分は**認証情報ではない。**

- IPアドレス・MACアドレス・ホスト名
- **シリアル番号**（DS18B20 の ROM は機器の個体識別子である）
- 実行環境の絶対パス、個人を特定できる記述

これらは検出器の対象外で、いまは**目視**に頼っていた。

---

## 2. Decision

### 2.1 環境固有の情報を**試験で見張る**

`tests/test_repo_hygiene.py` が追跡ファイルを走査する。CI で毎回走るので、
受入基準「リポジトリ単体を読んで、稼働環境や運用主体が特定できない」が
**ファイルが増えても保たれる。**

**目視の確認は続かない。** Issue の「初回 push 前に `git log -p` を目視で確認する」は
一度きりの作業であり、2回目以降の混入を止められない。

### 2.2 走査は**許可リストではなく除外リスト**

読まないのは画像・PDF・フォントだけで、**それ以外はすべて読む。**

`.py` と `.md` だけを見る形にすると、**新しい種類のファイルが黙って検査の外に出る。**
実際、最初は拡張子の許可リストで書いていて、`.jsonl` の試験データが
漏れていた（そこに小文字の ROM が入っていた）。

### 2.3 個体識別子は**明らかな仮の値**だけを使う

| 種類 | 使ってよい値 |
|---|---|
| IPアドレス | `127.0.0.1` / `0.0.0.0` / 文書用の予約範囲（RFC 5737） |
| DS18B20 の ROM | `28FF…` で始まる値（大小文字は問わない） |
| MACアドレス | 書かない |

ROM の2バイト目が `FF` になることは実物ではまず起きないので、
**`28FF` で始まらない ROM は実機の値だと判断できる。**

例に実環境のアドレスを使わない。例が要るなら予約範囲を使う。

### 2.4 `LICENSE` と宣言の**一致を試験で固定する**

`LICENSE`（Apache-2.0 の本文）は `56edff6` で既に置かれている。ここで足すのは
**宣言と本文がずれないようにする試験**である。

`pyproject.toml` の `license`、README の表記、`LICENSE` の本文は3か所に分かれている。
どれか1つだけ変わると、**宣言と条件が食い違う。** 附則の雛形（`[yyyy]` /
`[name of copyright owner]`）が埋まっていることも確かめる。

本文は**一字も変えない**ので、衛生の走査からは除外する。

### 2.5 `.env.example` は**変数名だけ**

値を書くと、雛形そのものが秘匿情報になる。
`=` の右側が空であることを試験で固定した。

## 3. Consequences

### 良くなること

- 環境固有の情報が**入った時点で CI が落ちる**（2.1）
- 新しい種類のファイルも自動的に検査に入る（2.2）
- 仮の値の形が決まっているので、実機の値との区別が付く（2.3）
- 宣言（`pyproject.toml` / README）と本文がずれない（2.4）

### 悪くなること・その緩和

| トレードオフ | 緩和策 |
|---|---|
| 正当な IP を文書に書けない | 予約範囲（RFC 5737）を使う。実環境を書く必要は無い |
| 走査が全追跡ファイルに及ぶ | 171 ファイルで 0.14 秒。規模が変わったら対象を絞る |
| 仮の ROM の形を覚える必要がある | 試験が落ちたときのメッセージに場所が出る。AGENTS.md のルール7に書いた |

---

## 4. 却下した代替案

| 案 | 却下理由 |
|---|---|
| 目視の確認だけにする | 2回目以降の混入を止められない（2.1） |
| 拡張子の許可リストで走査する | 新しい種類のファイルが黙って外に出る。実際に漏れた（2.2） |
| `detect-secrets` のプラグインとして書く | baseline の運用に乗せると「既知として許可」できてしまう。環境固有の情報に例外を作りたくない |
| ROM を伏せ字（`28XXXXXXXXXXXX01`）にする | JSON スキーマの試験データが壊れる。16進として妥当な仮の値のほうがよい |
| LICENSE の本文を要約する | 法的な文面を書き換えない。走査の対象からも外す（2.4） |
| 履歴を書き換えて過去の記述を消す | 既に公開されたものは消えない。**できることとできないことを分けて、できないほうは人に伝える**（§5-1） |

### §5-1 について

全コミットの著作者が個人のメールアドレスになっている。これは**ファイルの中身では
なく git のメタデータ**なので、本 PR の試験では止められない。

- 既に公開されている。**履歴の書き換えでは完全には消えない**
- 今後のコミットを変えるには、`git config user.email` を GitHub の
  noreply アドレスに切り替える（`<id>+<username>@users.noreply.github.com`）
- GitHub 側の「Keep my email addresses private」も併せて有効にする

**どう扱うかは本人の判断**なので、ここには選択肢だけを残す。
