## 1. Context

試作時の記録が `~/server_sensor_logs/` に残っている。これを取り込み経路へ
流し込めれば、**実機が無くても本物の推移で上位レイヤを試せる。**
本番開始後は当日のCSVからバグを再現する手段にもなる。

流し込むにあたって決めるべきことが、時刻の扱いを中心にいくつかある。

---

## 2. Decision

### 2.1 保存する時刻は**CSV の値**。「いま」にしない

再生でホスト受信時刻を現在時刻にすると、当時の推移ではなく
**「いま起きたこと」として保存される。** それでは当時のグラフを再現できず、
回帰テストのゴールデンデータにもならない。

`SimulatedClock`（#42）を行の時刻へ進めることで、取り込み経路（#8）を
素通しのまま過去の時刻で保存できる。ソースが時計を持つ設計がここで効く。

### 2.2 流し方は3つ。速度は**待ち時間にだけ**効く

| 指定 | 挙動 |
|---|---|
| `--speed 1`（既定） | 実時間再生。CSV の行間隔ぶん待つ |
| `--speed 60` | 時間圧縮再生 |
| `--bulk` | 一括投入。待たない |

**どれで流しても保存される内容は同じ。** 速度で値が変わると、
急いで流したテストと実運用で挙動が違うことになる（決定記録 0009 と同じ原則）。

`--speed 0` を一括投入にしない。0 は「速度」として意味を持たないため、
別のフラグにする。

### 2.3 列名の揺れを吸収する。知らない列と壊れた行は**捨てて続ける**

試作中のスクリプトは列名が揺れていた可能性がある。大文字・空白・BOM・別名を
正規化し、対応表に無い列は捨てる（決定記録 0003 §2.7 と同じ態度）。
時刻として読めない行も捨てる。

**1列の名前違いや1行の書式違いで、1日ぶんの再生が止まるほうが困る。**
ただし時刻の列が1つも見つからないファイルは拒否する。
それは「揺れ」ではなく別形式である。

### 2.4 `seq` / `up` は合成する。連続した値にする

CSV には無い。**連続した値を入れることで、再生では取りこぼし（FR-105）や
再起動（FR-106）の検出が意味を持たないことを明示する。**

欠測を再現したければ、CSV の空欄がそのまま `missing` になる。
そちらが再生で試せる欠測である。

### 2.5 `interval_ms` は最初の2行の間隔から推定する

期待サンプル数（決定記録 0002 §2.8）の母数になる。読めなければ 2.5 秒とみなす。
実測に近い値であることが重要で、正確さは要らない。

### 2.6 `dev` は `csv-replay`

`devices` テーブルで実機やモックと取り違えないための名前。

### 2.7 タイムゾーンは呼び出し側から受け取る

CSV の時刻はローカル時刻でオフセットを持たない（決定記録 0008 §2.8）。
ホストの設定に依存させない。既定は `Asia/Tokyo`。

### 2.8 再生した過去データも**保持期間の対象**である ★注意

古いCSVを再生すると、保持期間（30日）を過ぎた生データがそのまま入る。
次に `coldaisle-rollup` が走ると、**ロールアップされたうえで生データは消える**
（決定記録 0008 §2.4）。

これは正しい挙動である。保持期間は「データの出どころ」ではなく
「いつのデータか」で決まる。ただし**デバッグのために古いCSVを入れた場合、
生データは次の保持ジョブまでしか残らない。** 長く見たいなら
保持ジョブを止めるか、別の DB ファイルへ再生する。

---

## 3. Consequences

### 良くなること

- 実機が無くても**本物の推移**で上位レイヤを試せる。実際に
  2026-08-24 の記録（1,694サンプル / 11,858行）を投入し、
  API から当時の統計（min 22.81 / max 24.0 / p95 23.94℃）を引けることを確認した
- 本番開始後、当日のCSVから同じ入力を再現できる
- 取り込み経路を素通しで使うため、**再生と実機で通る道が同じ**。
  再生でだけ通る抜け道を作らない

### 悪くなること・その緩和

| トレードオフ | 緩和策 |
|---|---|
| 古いCSVの生データは保持ジョブで消える（2.8） | ロールアップは残る。長く見たいなら別 DB へ再生する |
| `seq` の連続性が本物ではない（2.4） | 再生で取りこぼし検出を試さない。試すのは `mock` の `dropout` シナリオ |
| 列名の揺れの吸収は当て推量 | 対応表を1箇所に置き、テストで固定した。増えたら足す |

---

## 4. 却下した代替案

| 案 | 却下理由 |
|---|---|
| 再生時のホスト時刻を「いま」にする | 当時の推移が再現できない。回帰テストにも使えない（2.1） |
| `--speed 0` を一括投入とする | 0 は速度として意味を持たない。別のフラグにする（2.2） |
| 知らない列でエラーにする | 1列の名前違いで1日ぶんの再生が止まる（2.3） |
| `seq` に飛びを作って通信断を再現する | CSV には届かなかった行の情報が無い。作れば嘘になる（2.4） |
| 実機の記録をリポジトリのフィクスチャにする | 環境固有の情報を public リポジトリへ持ち込まない（#41）。同じ体裁の合成データで試す |
