## 1. Context

`SerialSource` は**シリアルポートを開いてよい唯一の場所**（AGENTS.md ルール6）。

監視のソースとしての難しさは、値ではなく**繋がらない時間**の扱いにある。

- USB は抜ける。ケーブルも抜ける。デバイスは再起動する
- ESP32 は起動のたびにブートログを吐き、USB CDC はその途中から拾える
- 落ちてはいけない。**しかし黙って生き続けてもいけない**

---

## 2. Decision

### 2.1 **例外を上へ投げない。終端もしない**

抜線はこの層で処理し、再接続を待つ。投げるとデーモンが落ち、
**「監視が止まった」ことが誰にも伝わらない。**

`stream()` は終わらない。**抜線は「終わり」ではなく「いま届いていない」**である。
デーモンの読み取りスレッドはデーモンスレッドなので、停止時は放置してよい。

黙って止まることにはならない。サンプルが出ないだけなので、
無音が続けば `SENSOR_FAULT`（FR-401）が鳴る。**再接続中も鳴り続ける。**

### 2.2 再接続は **1 → 2 → 4 …… 30 秒**

上限を置く。置かないと、長時間の抜線のあと復帰までに何時間もかかる。

**間隔を戻すのは「開けた」ときだけ。** 開けなかった場合まで戻すと、
いつまでも開けないポートを1秒ごとに叩き続ける（指数バックオフの意味が無い）。
`_read_from()` が「開けたか」を返し、呼び出し側が決める。

### 2.3 読めない行は**捨てるが、数は残す**

行頭が `{` でない行、JSON として読めない行、未知の種別は捨てる（FR-103）。

**1行ごとにはログへ出さない。** ブートログで埋まって、本物の障害が見えなくなる。
接続が切れたときに**その接続で捨てた数**を1行出す。空行は数えない
（数えると、溢れた数が意味を持たなくなる）。

### 2.4 **非有限値は行ごと捨てる**

決定記録 0003 §2.8（実装必須）が取り込み側に課している責務がここである。

```python
json.loads(text, parse_constant=_reject_constant)
```

`parse_constant` は `NaN` / `Infinity` の**字面**しか見ない。`1e999` は
`float()` を通って `inf` になるので、**値そのものも確かめる。**

`readings.value`（REAL）に入ると、そのメトリクスの min / max / mean が
恒久的に壊れる。生データを30日で消したあとはロールアップからも取り除けない。

行の解釈は `ingest.protocol.decode_line()` に置いた。**契約の隣に置く。**
`SerialSource` は「いつ読むか」だけを持つ。

### 2.5 入口では**契約どおりに厳しく読む**

`decode_line` は電文の**唯一の入口**である。ここが緩いと、契約に反する値が
そのまま保存まで届く。

- **型を強制変換しない**（`"1042"` を `1042` にしない）。`strict=True` で読む
- `err` は配列でなければ**行ごと捨てる。** `null` は例外になり、文字列は
  `tuple("abc")` で1文字ずつの理由に化ける
- `ds18b20` には `gpio` / `rom` / `res` を要求する（決定記録 0003 §2.4）。
  **`rom` の無いバナーを基準として記録すると、次の差し替えで比べる相手が無い**
- `rom` は大文字16進16桁。小文字を通すと、同じプローブを**別物として比べる**
- `sensors` は空にしない

**内部の組み立てまでは締めない。** `strict=True` を当てるのは `model_validate`
の呼び出し側（＝電文の入口）だけで、`MockSource` などが Python の値から作る
経路は今までどおり。締める場所と使いやすさの場所を分ける。

判定は `schemas/device_v1.schema.json` とは別に書いてある（実行時に
`jsonschema` を持ち込まないため）。**別々である以上、ずれる。**
契約の違反例（`tests/fixtures/device_v1_schema_violations.jsonl` の13行）を
そのまま通して、**1行でも通ったら落ちる**ようにした。

### 2.6 ポートは**名前の順で選ぶ**

見つかった順にすると、**起動ごとに読む相手が変わりうる。**
候補が複数あることは警告に出す（黙って1つ選ぶと、別の機器を読んでいても気づけない）。

並べ替えるのは**選ぶ側**（`_choose`）。探す関数が何を返しても選び方は変わらない。

### 2.7 `pyserial` を import するのは**1つの関数の中だけ**

`open_port()` の中で import する。実機が無い環境や `pyserial` を入れていない
環境で、**モジュールの import そのものが失敗しない**ようにする。

差し替え可能にしてあるので、試験は偽のポートで回る（受入基準「CI 実行可能」）。

### 2.8 実機の抜き差しは `@pytest.mark.hardware`

CI では回らない（AGENTS.md ルール7）。手元で `uv run pytest -m hardware`。

## 3. Consequences

### 良くなること

- USB を抜いてもデーモンが落ちず、挿し直すと戻る（2.1 / 2.2）
- ブートログでログが埋まらない（2.3）
- 非有限値が DB へ入らない（2.4）
- **契約に反する電文が保存まで届かない**（2.5）
- **#11 のファームウェアが実際に読める**（`firmware/sample_output.jsonl` を試験で通している）

### 悪くなること・その緩和

| トレードオフ | 緩和策 |
|---|---|
| `stream()` が終わらないので、単体で回すと止まらない | 試験は `max_reconnects` で回数を切る |
| 捨てた行の中身が残らない | 数は残る。中身が要るなら `--log-level DEBUG` を足す（未実装） |
| 候補が複数あるとき、選び方が名前順という約束に依存する | 明示指定（`--port`）ができる |

## 4. 却下した代替案

| 案 | 却下理由 |
|---|---|
| 切断で例外を投げてデーモンを落とす | 監視が止まったことが誰にも伝わらない。**落ちるのが最悪**（2.1） |
| 切断で `stream()` を終える | デーモンは「ソースが尽きた」として正常終了する。同じく黙って止まる |
| 再接続の間隔を固定にする | 短いと叩き続け、長いと復帰が遅い（2.2） |
| 開けなかったときも間隔を戻す | いつまでも開けないポートを1秒ごとに叩く（2.2。**最初の実装がこれだった**） |
| 捨てた行を1行ずつログに出す | ブートログで埋まり、本物の障害が見えなくなる（2.3） |
| 非有限値をチャネルだけ `null` にする | 決定記録 0003 §2.8 は**行ごと**と定めている。正規化側は二重の防御（2.4） |
| 入口を緩いまま使う | 契約に反する値が保存まで届く。`"26.4"` が数値として入る（2.5） |
| 実行時に `jsonschema` でスキーマを直接当てる | スキーマはパッケージの外にあり、配布物に入らない。試験で一致を縛るほうを採った（2.5） |
| `err` が壊れていたら例外を投げる | `SerialSource` が切断と取り違え、健全なポートを閉じて開き直す（2.5） |
| 見つかった順にポートを選ぶ | 起動ごとに読む相手が変わりうる（2.6） |
| `pyserial` をモジュール先頭で import | 入れていない環境で import 自体が失敗する（2.7） |
