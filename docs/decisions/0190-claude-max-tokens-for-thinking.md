## 1. Context

導入先は 0143 の Claude API（`claude-haiku-5-5`）で、`config/ai.yaml` の `max_tokens` は全体・`anthropic:` とも `1024`。
送る値は 2 つの小さいほう（`claude_provider.py`）。0143 §2.6 は `stop_reason: max_tokens`（途中で切れた）の応答を「利用不可」として捨てる。

2026-11-26 に、Slack のボットが「今日の状況って普段と比べてどうなの？」に「いま AI が使えません」と返した。journal の理由は
`stop_reason: max_tokens`（ツールは 2 つ呼べていて、最後の答えの生成で切れた）。同じ理由で、アラートの説明（`coldaisle-daemon`）が
2026-11-02 から 17 回切れて捨てられていた。通知そのものは届き、説明が付かないだけだった。日次レポートでは起きていない。

原因は、**Haiku 5.5 は `thinking` を送らないと adaptive thinking が既定で有効**で（`effort` の既定は `medium`）、
**考えた分の token も `max_tokens` に数えられる**こと。0143 §2.5 は「`thinking` を送らない（モデルの既定のまま）」と決めたが、
1024 は「今の `max_tokens` と同じ値」として置いたもので、考える分を見込んでいなかった。

## 2. Decision

### 2.1 値

`config/ai.yaml` の次の 2 か所を `1024` から **`4096`** にする（§5 の 1・2）。

| 設定 | 前 | 後 | 効くところ |
|---|---|---|---|
| `max_tokens`（全体） | 1024 | **4096** | OpenAI 互換の Provider が送る値と、Claude API の小さいほうを取る片方 |
| `anthropic.max_tokens` | 1024 | **4096** | Claude API の小さいほうを取るもう片方。3 つの経路（日次レポートの所見・アラートの説明・Slack のボット）と Server Health の要約に共通 |

- 経路ごとの値は持たない。切れて捨てられているのはボットとアラートの説明の 2 つの経路で、どちらも同じ原因なので、1 つの値で直す
- **切れた応答を捨てる規則（0143 §2.6）は変えない。** 4096 でも切れれば、今までどおり「利用不可」として捨て、テンプレートを出す
- `effort` は `null`（送らない）のまま。考える量を減らす方向ではなく、考えた後に答える余地を作る
- `timeout_s`（30 s）は変えない。ボットの答えは今まで最長 6.4 s で、上限が 4 倍になっても届く見込み。届かなければ今までどおり「利用不可」になるだけ

### 2.2 費用

`claude-haiku-5-5` の出力は 100 万 token あたり $0.50。1 回あたり出力 4,096 token・入力 3,000 token の最悪の場合で約 $0.0024。
0143 §2.5 の上限（3 プロセス × 1 日 200 回）まで呼んでも 600 回 × $0.0024 ≒ **$1.4 / 日**。実際は日次レポート 1 回 + アラートの件数 +
ボットの質問（1 日 100 回まで。0168）で、桁が 1〜2 小さい。課金の正本は Console の使用量と spend limit のまま（0143 §5 の 1）。

### 2.3 ローカル LLM の経路

全体の `max_tokens` は OpenAI 互換の Provider（PAW の vLLM・0163）にも効く。導入先は今 Claude API を使っているので、この経路は動いていない。
ローカル LLM に戻すときに、0166 の NFR-04 の測り方（要求の本文の `max_tokens` を 1024 にして送る）とあわせて値を見直す（§5 の 3）。

### 2.4 反映

`config/ai.yaml` だけの変更で、0167 §2.1 の区分は **O**（fand の import の閉包の外）。導入先へは 0189 の更新（`0cf5aba` → main）と同じ回に入れる。
効くのは各プロセスが設定を読み直したとき（`coldaisle-daemon`・`coldaisle-slackbot` は更新の手順で起動し直す。`coldaisle-report` は次の実行から）。

### 2.5 試験（実機不要。ルール 7）

- `config/ai.yaml` を読んだ `AiSettings` の `max_tokens` と `anthropic.max_tokens` が 4096 で、Claude API の要求の本文の `max_tokens` が 4096 になる

## 3. Consequences

### 良くなること

- 考えてから答える質問（比べる・まとめる）でも、ボットの答えとアラートの説明が付く

### 悪くなること・その緩和

| 悪くなること | 緩和 |
|---|---|
| 1 回あたりの最大の費用が約 3 倍になる | 実際に使う量は考える量と答えの長さで決まり、上限は暴走の蓋。1 日の回数の上限はそのまま。Console の spend limit が正本 |
| 長い答えを書けるようになる | Slack は `max_reply_chars`（3000 字）で切り詰める（0168）。system の指示の「短く答える」はそのまま |
| 1 回の応答に時間がかかりうる | `timeout_s` を超えれば今までどおり「利用不可」。通知は待たない（説明は後追い。0016） |

## 4. 却下した代替案

| 案 | 却下の理由 |
|---|---|
| ボットの経路だけ上限を上げる | アラートの説明も同じ原因で 17 回捨てられていた。所有者は全体を上げる案を選んだ（§5 の 1） |
| `effort` を `low` にして考える量を減らす | 上限 1024 に収まる保証が無く、答えの質も下がりうる。Haiku 5.5 で `low` の効きを確かめていない（0143 §2.5 の「対応を確かめたモデルでだけ設定する」） |
| `thinking` を明示して切る | Haiku 5.5 は `effort` `high` 以下でしか切れず、0143 §2.5 で送らないと決めた。考えた方が比べる質問の答えは良い |
| 切れた応答の文を採用する | 途中で切れた所見を事実のように出しうる。0143 §2.6 のまま捨てる |
