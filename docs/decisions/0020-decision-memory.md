## 1. Context

**較正値と閾値は運用中に何度も変わる。** 会話履歴やコミットログに散らばると、
3ヶ月後に「いまの閾値はいくつだっけ」が分からなくなる。

このプロジェクトは同じ問題を決定記録（`docs/decisions/`）で解いている。
**運用中に変わる値**は決定記録に置けない（記録は書き換えないため）ので、
別の置き場所と別の作法が要る。

---

## 2. Decision

### 2.1 記録するのは**設定と DB にある事実だけ**

`config/rules.yaml` の閾値、`config/calibration.json` のオフセット、
`devices` テーブルのセンサー構成。**推測しない。** 各行が出所を持つ。

ルールは**種類ごとに書き分けない**（モデルをそのまま書き出す）。
項目が増えたときに書き漏らさないため。**無効なルールも「無効」として記録する。**
省くと「書いていない＝有効」と読まれる。

### 2.2 **`--apply` を付けたときだけ書く**

要件 Q-12 と構想メモ §23 の「全自動保存にせず、確認を経由する」。

既定は差分を表示して終わる。**端末の出力が確認の場**である。
`--commit` は `--apply` と一緒でなければ拒否する（書いていないものはコミットできない）。

### 2.3 Current Facts は**印で囲んだ区画**、History は**積むだけ**

```markdown
<!-- coldaisle:current:start -->
| キー | 項目 | 値 | 出所 | 記録日 |
<!-- coldaisle:current:end -->
```

- 区画は毎回**丸ごと作り直す**。同じキーが2行あると、どちらが本当か分からない
- **区画の外は触らない。** 人が書いた文章を機械が壊さない
- History は書き換えず、新しいものを上に積む

**変わっていない項目の記録日は据え置く。** 毎回今日にすると、
「いつからこの値なのか」という**いちばん知りたいこと**が消える。

### 2.4 古い記録に **`Superseded by` を追記する**

受入基準の「過去の値も Superseded として残っており、**検索で誤って最新扱い
されない**」がこれ。

**新しい記録に `Supersedes` を書くだけでは足りない。** 古い記録**だけ**を読んだ人が
失効した値に従う。決定記録の運用ルール（`docs/decisions/README.md` の「追記のみ」）と
同じ理由・同じ形にした。

各段落を `Key: \`rule.recirculation\`` で始めるのは、**あとから印を付けるために
機械が読めるようにする**ためである。印は先に付ける（あとだと、いま積んだ記録に
「これは古い」と書いてしまう）。

### 2.5 `Status:` は **`Observed`**

決定記録の `FINAL` は使わない。**coldaisle が観測できるのは「設定が変わった」ことだけ**で、
それが確定した決定かどうかは分からない。人が読んで書き換える前提の値にする。

### 2.6 git commit は**任意**、push はしない

`--commit` を付けたときだけ `git add` と `git commit` を1回ずつ。
シェルを通さず引数を固定で渡す。失敗しても例外にしない（ファイルは既に書けている）。

これは AI レイヤのツールではない（AGENTS.md ルール1 の対象外）。
`ai/` からこの経路へは届かない。

## 3. Consequences

### 良くなること

- いまの閾値・較正値が**1ファイルで分かる**（2.3）
- 古い値を最新と読み違えない（2.4）
- 勝手に書かれない（2.2）
- 人が書いた文章と機械が作る表が**同じファイルに共存できる**（2.3）

### 悪くなること・その緩和

| トレードオフ | 緩和策 |
|---|---|
| 人が `--apply` を忘れると記録が古いままになる | 差分は毎回表示される。cron から日次で回せば気づく |
| 値の表現が機械的（`threshold=5, clear=4`） | 出所を併記してあるので、詳しくは設定ファイルを見れば分かる |
| `Status: Observed` のままの記録が溜まりうる | 人が確定させたら書き換える。**書き換えてよいのは Status だけ** |

---

## 4. 却下した代替案

| 案 | 却下理由 |
|---|---|
| 変化を検出したら自動で書く | 要件 Q-12。**気づかないうちに記録が書き換わる**のがいちばん困る（2.2） |
| ファイル全体を毎回生成する | 人が書いた文章を消す（2.3） |
| 現在値を History から読み取る | 「いまの値」を知るのに履歴を遡ることになる。1箇所に置く意味が無くなる |
| 新しい記録の `Supersedes` だけで足りるとする | 古い記録だけを読んだ人が失効した値に従う（2.4） |
| `Status: FINAL` と書く | 設定が変わったことしか観測していない。確定は人の判断（2.5） |
| 決定記録（`docs/decisions/`）に混ぜる | あちらは**書き換えない**記録。運用中に変わる値の置き場所ではない |
| 値の履歴を DB に持つ | 人が読んで直せる形（Markdown + git）であることが目的（構想メモ §19） |
