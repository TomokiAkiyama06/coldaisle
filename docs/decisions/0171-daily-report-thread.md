# 決定記録 0171: 日次レポートを Slack では「◯月◯日の振り返り」の親の投稿とそのスレッドで送る

- **種別**: Decision Record
- **Status**: Proposed
- **Date**: 2026-10-26
- **Supersedes**: なし
- **関連**: [`0013`](0013-notifications.md) / [`0147`](0147-slack-alert-graph.md) §2.1 / `docs/requirements.md` FR-506 / AGENTS.md「絶対に守るルール」9
- **対象 Issue**: #380

## 1. Context

日次レポート（`coldaisle-report`、FR-506）は、毎朝 1 通の Slack の投稿として送っている。本文は Markdown の表を含み長いので、
チャンネルを日をまたいで眺めると、レポートの本文がアラートの投稿の間を大きく占める。

所有者から、まず「◯月◯日の振り返り」という題だけの投稿を送り、本文はそのスレッドへの返信にしたいという要望があった（2026-10-26）。
チャンネルには日ごとの題だけが並び、中身はスレッドを開いて読む形になる。

スレッドへ返すには、送った投稿の `ts` が要る。0147 §2.1 のとおり、Bot トークン（`COLDAISLE_SLACK_BOT_TOKEN` と `COLDAISLE_SLACK_CHANNEL` の両方）が
あるときは `chat.postMessage` で送り `ts` を得られるが、Webhook は `ts` を返さない。

## 2. Decision（所有者の回答: 親は題だけ・Webhook だけなら今と同じ 1 通）

### 2.1 送り方

| 宛先 | 送り方 |
|---|---|
| Slack（Bot トークンとチャンネルの両方あり） | 1. 親: 題だけ（`📄 10月25日の振り返り`）を `chat.postMessage` で送り、`ts` を得る 2. 本文: 今のレポートの本文（長さの上限・切り詰めは今のまま）を、その `ts` のスレッドへの返信で送る |
| Slack（Webhook だけ） | **今と同じ 1 通**（スレッドにできない） |
| LINE・stdout ほか | 今のまま |

- 題は対象日（レポートが扱う日。送る日ではない）の月と日。年は付けず、0 埋めしない（`10月5日`）
- 題の書式は設定（`config/report.yaml`）に置く（ルール 9）。既定は `📄 {month}月{day}日の振り返り`
- 親の投稿に要約・件数の行は付けない（所有者の回答）
- レポートは今のまま `Router` を通さない（連投の抑制・夜間の方針はアラートの都合。`report.send` の docstring の理由のまま）

### 2.2 失敗したとき（本文を黙って失わない）

| 失敗 | 扱い |
|---|---|
| 親が送れない | スレッドにせず、今と同じ 1 通を送る（今の再試行・`DeliveryError` の扱いのまま）。それも失敗すれば今と同じく失敗としてログに残し、ほかの宛先へ進む |
| 親は送れたが本文の返信が送れない | 本文をスレッドではなくチャンネルへ 1 通で送る。それも失敗すれば失敗としてログに残す（親だけが残る） |

`sent`（送れた宛先の数）は、本文がどこかに届いた宛先だけを数える。

### 2.3 試験（実機不要。ルール 7）

- Bot あり: 親（題だけ）→ 返信（`thread_ts` が親の `ts`）の順で送られる
- Webhook だけ: 今と同じ 1 通。Slack 以外: 変わらない
- 親の失敗・返信の失敗のそれぞれで、本文が §2.2 のとおりに届く

### 2.4 導入先への反映

`report.py`・`notify/`・`config/report.yaml` は 0167 の区分 O で、共通の確認だけで入れられる。翌朝のレポートで見た目を確かめる。

## 3. Consequences

### 良くなること

- チャンネルには日ごとの題だけが並び、アラートの投稿が埋もれない
- 日付で探しやすい（題が「◯月◯日の振り返り」）

### 悪くなること・その緩和

| 悪くなること | 緩和 |
|---|---|
| 本文を読むのにスレッドを開く手間が 1 つ増える | 所有者の要望。モバイルでもスレッドは 1 タップで開ける |
| スレッドへの返信はチャンネルの未読・通知にならない | 親の投稿が通知になるので、届いたことは分かる |
| Slack への呼び出しが 1 日 1 回から 2 回に増える | `chat.postMessage` の 1 回ぶん。上限に遠い |
| Webhook だけの導入では形が変わらない | 所有者の回答（今と同じ 1 通）。スレッドにしたいときは Bot トークンを置く（`docs/notifications.md` 1a） |

## 4. 却下した代替案

| 案 | 却下した理由 |
|---|---|
| 親に要約の 1 行（アラートの件数・欠測）を付ける | 所有者が「題だけ」を選んだ |
| Webhook のときは題と本文を別々の 2 通で送る | スレッドにならないのに投稿が 2 つに増える。所有者が「今と同じ 1 通」を選んだ |
| 本文の返信が失敗したら親を消す | `chat.delete` の権限が要り、消す操作の失敗も扱うことになる。親が残っても本文はチャンネルへ届く（§2.2） |
| `Router` を通してスレッドの仕組み（0147 の送信スレッド）を使う | レポートは `Router` を通さない方針（連投の抑制・夜間の方針が当たらない）。日報は 1 日 1 回なので、同じ処理の中で 2 回送れば足りる |
