# 決定記録 0171: 日次レポートを Slack では「◯月◯日の振り返り」の親の投稿とそのスレッドで送る

- **種別**: Decision Record
- **Status**: Proposed
- **Date**: 2026-10-26
- **Supersedes**: [`0017`](0017-daily-report.md) §2.4（出力先 `var/reports/` へ毎日ファイルを書く）と §2.5 の末尾の
  「全文はファイルに残し、通知は長ければ切る」のみ（0017 の集計・欠けの扱い・`Router` を通さない方針は有効）
- **関連**: [`0013`](0013-notifications.md) / [`0017`](0017-daily-report.md) / [`0147`](0147-slack-alert-graph.md) §2.1・§2.5 /

- **対象 Issue**: #380

## 1. Context

日次レポート（`coldaisle-report`、FR-506）は、毎朝 1 通の Slack の投稿として送っている。本文は Markdown の表を含み長いので、
チャンネルを日をまたいで眺めると、レポートの本文がアラートの投稿の間を大きく占める。

所有者から、まず「◯月◯日の振り返り」という題だけの投稿を送り、本文はそのスレッドへの返信にしたいという要望があった（2026-10-26）。
チャンネルには日ごとの題だけが並び、中身はスレッドを開いて読む形になる。

スレッドへ返すには、送った投稿の `ts` が要る。0147 §2.1 のとおり、Bot トークン（`COLDAISLE_SLACK_BOT_TOKEN` と `COLDAISLE_SLACK_CHANNEL` の両方）が
あるときは `chat.postMessage` で送り `ts` を得られるが、Webhook は `ts` を返さない。

## 2. Decision（所有者の回答: 親は題だけ・Webhook だけなら今と同じ 1 通・要点と表を分ける・表は日本語の画像・ファイルに保存しない）

2026-10-26 にデモ（10 月 25 日分を Bot で親とスレッドの形で 1 回送った）を見た所有者の判断で、本文の形と保存も合わせて決める。
デモでは本文の大半が 38 行の Markdown の表で、3500 文字の上限で切られ、末尾の AI の所見が途中で消えた。

### 2.1 送り方

| 宛先 | 送り方 |
|---|---|
| Slack（Bot トークンとチャンネルの両方あり） | 1. 親: 題だけ（`📄 10月25日の振り返り`） 2. 返信 1: 要点（§2.2） 3. 返信 2: 測定値の表の画像（§2.3） |
| Slack（Webhook だけ） | **今と同じ 1 通**（スレッドにも画像にもできない。今の Markdown の本文） |
| LINE・stdout ほか | 今のまま（今の Markdown の本文） |

- 題は対象日（レポートが扱う日。送る日ではない）の月と日。年は付けず、0 埋めしない（`10月5日`）
- 題の書式は `config/report.yaml` に置く（ルール 9）。既定は `📄 {month}月{day}日の振り返り`
- 親の投稿に要約・件数の行は付けない
- レポートは今のまま `Router` を通さない（0017 §2.5）

### 2.2 返信 1: 要点

切らずに 1 投稿に収まる長さにする。中身は次の順:

1. アラート: 当日の発火の件数と前日の件数、日の終わりに続いているアラートの名前と重大度
2. AI の所見（作れたときだけ。今の「AI 生成・未検証」の印のまま）。**切らない**
3. 主な値: `config/report.yaml` の一覧に書いた metric の最高値（既定は室温・GPU コア温度・CPU Package 温度・12V-2x6 コネクタ外装温度・GPU 消費電力・CPU Package 消費電力）。
   その日の値が無い metric は書かない
4. 欠測: その日の欠測率が 0 % でない metric の表示名だけ（率は表の画像で見る）
5. ダッシュボードのリンク（今のまま）

### 2.3 返信 2: 測定値の表の画像

- 今の「測定値」の表（最低・平均・最高・前日比・欠測・収録）を、日本語の表示名のまま PNG に描く。行は交互に薄く塗り、値の無い行（欠測 100 % など）は薄い色の文字にする
- 描くのは `coldaisle-report` だけで、Pillow を使う（依存に足す）。フォントは導入先の日本語のフォントのファイルを `config/report.yaml` で指す
  （この機械では Noto Sans CJK）。**取り込み・API・fand・Learned のプロセスには載せない**（0147 §2.5 の「取り込みに画像ライブラリを載せない」は保つ）
- 画像は 0147 と同じ `files.getUploadURLExternal` → `files.completeUploadExternal`（`thread_ts` 付き）で親のスレッドへ上げる
- **描けないとき**（フォントのファイルが無い・Pillow の失敗）は、表を Markdown の本文の返信で送る。画像の失敗で日報を止めない
- 決定論的に描く（同じ入力から同じ bytes）。LLM は関わらない（ルール 1・8）

### 2.4 ファイルに保存しない

- `var/reports/YYYY-MM-DD.md` へ毎日書くのをやめる（0017 §2.4 を置き換え）。`config/report.yaml` の `output_dir` は消す
- 手で読みたいときは今のまま `coldaisle-report --date <日> --no-send --print` で標準出力へ出す
- 導入先に残っている過去のファイルは、コードでは消さない（所有者が要らなければ手で消す）
- Webhook・LINE で送る 1 通は、長ければ今と同じく切る。末尾の「…（全文は YYYY-MM-DD.md）」は「…（続きはダッシュボードで）」に直す

### 2.5 失敗したとき（本文を黙って失わない）

| 失敗 | 扱い |
|---|---|
| 親が送れない | スレッドにせず、今と同じ 1 通（Markdown の本文）を送る（今の再試行・Webhook への送り直しのまま） |
| 親は送れたが返信 1 が送れない | 要点をスレッドではなくチャンネルへ 1 通で送る |
| 画像が描けない・上げられない | 表を Markdown の本文の返信（それも失敗すればチャンネル）で送る |
| どれも送れない | 今と同じく失敗としてログに残し、ほかの宛先へ進む |

`sent`（送れた宛先の数）は、要点がどこかに届いた宛先だけを数える。

### 2.6 試験（実機不要。ルール 7）

- Bot あり: 親 → 要点（`thread_ts` が親の `ts`）→ 画像（同じ `thread_ts`）の順
- Webhook だけ: 今と同じ 1 通。Slack 以外: 変わらない
- 要点が切れない・既定の metric の一覧・欠測の名前
- 画像: 同じ入力で同じ bytes・フォントが無いときは Markdown の表で送る
- 親・返信・画像のそれぞれの失敗で §2.5 のとおりに届く
- ファイルを書かない（`--print` は今のまま）

### 2.7 導入先への反映

`report.py`・`notify/`・`config/report.yaml` は 0167 の区分 O だが、Pillow を依存に足すと `uv.lock` が変わり **区分 F**（R1〜R3）になる。
#378（0170。同じく F と I）と同じ更新で入れる。

## 3. Consequences

### 良くなること

- チャンネルには日ごとの題だけが並び、アラートの投稿が埋もれない
- 日付で探しやすい（題が「◯月◯日の振り返り」）
- 要点が短くなり、AI の所見が切れない。表は画像で崩れずに読める
- 生活の傾向を含むファイルが導入先に毎日たまらない

### 悪くなること・その緩和

| 悪くなること | 緩和 |
|---|---|
| 本文を読むのにスレッドを開く手間が 1 つ増える | 所有者の要望。モバイルでもスレッドは 1 タップで開ける |
| スレッドへの返信はチャンネルの未読・通知にならない | 親の投稿が通知になるので、届いたことは分かる |
| Slack への呼び出しが 1 日 1 回から 4〜5 回に増える（親・要点・画像の 3 回の上げ） | 1 日 1 回のジョブで、上限に遠い |
| 画像ライブラリ（Pillow）が依存に増え、反映が区分 F になる | 使うのは `coldaisle-report` だけで、取り込み・fand には載せない。#378 と同じ更新で入れる（§2.7） |
| 日本語のフォントのファイルに依存する | 無ければ Markdown の表で送る（§2.3）。場所は設定 |
| 過去の日報の全文が残らない | 集計値は DB とロールアップに残り、`--print` でいつでも作り直せる。Slack のスレッドも残る |
| Webhook だけの導入では形が変わらない | 所有者の回答（今と同じ 1 通）。スレッドにしたいときは Bot トークンを置く（`docs/notifications.md` 1a） |

## 4. 却下した代替案

| 案 | 却下した理由 |
|---|---|
| 親に要約の 1 行（アラートの件数・欠測）を付ける | 所有者が「題だけ」を選んだ |
| Webhook のときは題と本文を別々の 2 通で送る | スレッドにならないのに投稿が 2 つに増える。所有者が「今と同じ 1 通」を選んだ |
| 本文の返信が失敗したら親を消す | `chat.delete` の権限が要り、消す操作の失敗も扱うことになる。親が残っても要点はチャンネルへ届く（§2.5） |
| 表を 2 つ目の返信に Markdown のまま送る | デモで見にくかった。所有者が画像を選んだ |
| 表を英数字だけの画像にする（今のグラフと同じ標準ライブラリの描き方） | 行の名前が metric 名になり読みにくい。所有者が日本語の画像を選んだ |
| 表を箇条書きにする | 所有者が画像を選んだ |
| ファイルの保存を続ける・保存期間を決めて消す | 所有者が保存をやめるを選んだ |
| `Router` を通してスレッドの仕組み（0147 の送信スレッド）を使う | レポートは `Router` を通さない方針（連投の抑制・夜間の方針が当たらない）。日報は 1 日 1 回なので、同じ処理の中で順に送れば足りる |
