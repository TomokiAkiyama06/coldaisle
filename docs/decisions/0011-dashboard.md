## 1. Context

Issue #17 は「**開発用・フォールバック用に留め、作り込まないでください**」と
但し書きを持つ。本番UIは Workspace 側（Tauri + React）が担当する（決定 D-12）。

したがってここでの判断はすべて「**最小で、壊れ方が分かりやすいこと**」を優先する。

---

## 2. Decision

### 2.1 Chart.js を使わない ★要件の技術スタックからの逸脱

要件 §11 はフロントを「Vanilla JS + Chart.js」としているが、
**Chart.js を読み込まず、依存の無い SVG で描く。**

理由は3つ。

1. **オフラインで見えなくなる。** CDN から読むと、回線の無い場所で
   グラフだけが消える。監視の道具が「見えないことに気づけない」壊れ方をしてはいけない
2. **同梱すると third-party のバンドルを public リポジトリへ持ち込むことになる**（#41）。
   ライセンス表記と更新の管理も増える
3. **作り込まない**という但し書きに対して、折れ線1種類のために
   ライブラリを1つ増やすのは釣り合わない。実装は SVG で 100 行に収まった

**この判断は要件の記述と食い違う。** 本番UIは Workspace 側なので影響範囲は
開発用の画面に限られるが、承認が要る。差し戻す場合、データ取得の部分は
そのままで描画だけ差し替えられる。

### 2.2 静的アセットは API ルートの**後ろ**にマウントする

先に置くと `/api/v1/...` まで静的配信に飲まれる。順序に依存する構造なので、
**API が先に当たること**をテストで固定した。

書き込み系が増えていないこと（FR-307）も、ダッシュボード追加後に確かめている。

### 2.3 欠測では線をつながない

折れ線は `value === null` で切る。つなぐと**その間も測れていたように見える。**
欠測は欠測として見える必要がある（要件 §5.3 の品質フラグと同じ考え方）。

### 2.4 品質は色と文言の両方で示す

カードの左辺の色（4値それぞれ）とバッジの日本語を両方出す。
色だけだと見分けにくく、印刷や色覚特性で落ちる。

**4値それぞれに見た目が定義されていること**をテストで固定した。
1つでも欠けると、異常なカードが正常なカードと同じに見える。

### 2.5 データが古いとき・未来のときは画面全体で言う

- 古い（`stale`）→ 赤帯で「取り込みが止まっている可能性」
- 1件も無い → 赤帯で「デーモンを確認」
- **受信時刻が未来** → 赤帯で「時計のずれ、または圧縮再生中の DB」

3つ目は、時間圧縮の再生中に API を見た場合に起きる（決定記録 0007 §2.11）。
`data_age_seconds` は負になる。**「-491秒前」と出しても読み手に何も伝わらない**ため、
何が起きているかを文で出す。

### 2.6 API から来た文字列を HTML として組み立てない

`textContent` だけを使い、`innerHTML` / `outerHTML` / `insertAdjacentHTML` /
`document.write` を使わない（要件 §7.4）。デバイスの `err` やアラートの
`detail` は外部由来の文字列である。**使っていないことをテストで固定した。**

### 2.7 更新は WebSocket + 5秒ごとの問い合わせ

現在値は WebSocket で押し出される（FR-306、NFR-03 の3秒以内を満たす）。
health とアラートは5秒ごとに問い合わせる。履歴は期間切替時と60秒ごと。

WebSocket が切れたら**指数バックオフで再接続し、その間も状態を出し続ける**
（「切断（8秒後に再接続）」）。黙って止まらない。

## 3. Consequences

### 良くなること

- 外部への参照がゼロ。オフラインでも全機能が動く（テストで固定）
- 異常の見え方が「色 + 文言 + 画面全体の帯」の3段になり、見落としにくい
- 依存が増えないため、`uv sync` だけで動く状態が保たれる

### 悪くなること・その緩和

| トレードオフ | 緩和策 |
|---|---|
| グラフの機能が乏しい（ズーム・ツールチップが無い） | 本番UIは Workspace 側。ここは開発用（Issue の但し書き） |
| 要件の技術スタックと食い違う（2.1） | 本記録で明示し、承認を求める。描画だけ差し替えられる |
| 見た目そのものは自動で検証していない | 「壊れていたら気づける」線（外部参照・品質4値・XSS・エンドポイント）をテストで引いた |

---

## 4. 却下した代替案

| 案 | 却下理由 |
|---|---|
| Chart.js を CDN から読む | オフラインでグラフだけ消える。監視の道具として最悪の壊れ方（2.1） |
| Chart.js を同梱する | third-party のバンドルを public リポジトリへ持ち込む（#41）。折れ線1種類には過剰（2.1） |
| 欠測を直線で補間する | 測れていない区間が測れていたように見える（2.3） |
| 品質を色だけで示す | 色覚特性・印刷で落ちる（2.4） |
| 負の経過秒数をそのまま表示する | 読み手に何も伝わらない（2.5） |
| ブラウザ自動テストを入れる | 依存とCIの重さが「作り込まない」に釣り合わない。代わりに壊れ方の線を引いた |
