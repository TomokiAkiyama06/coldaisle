# 決定記録 0006: GPU Mode を2段階にし、`gpu_state = mixed` を異常として扱う

- **種別**: Decision Record
- **Status**: FINAL（2026-08-24 承認）
- **Date**: 2026-08-24
- **Supersedes**: [`0001-initial-project-decisions.md`](0001-initial-project-decisions.md) D-19
- **関連**: [`0002-metric-naming.md`](0002-metric-naming.md) §2.6 / #36 / #37
- **対象 Issue**: #36

---

## 1. Context

0001 D-19 は GPU Mode を **AI / Shared / Compute の3段階**とし、
Shared を「小型モデルのみ常駐」と定義していた。

その後、**Kaggle 実行時にローカルAIを併用しない**方針が確定した。
Shared は「両方を少しずつ動かす」ための段階であり、併用しないなら使われない。

一方で、`sys.gpu_state`（NVML から観測した実際の状態、0002 §2.6）の
`mixed` は別の話である。**切り替えに失敗して両方動く状態は物理的にありえる。**
運用上起きない想定と、観測上ありえないことは違う。

---

## 2. Decision

### 2.1 GPU Mode（Workspace 側の指令値）は AI / Compute の2段階

**Shared を廃止する。** 利用者が選ぶのは「AI を動かす」か「Compute に明け渡す」かの
2択になる。中間段階を残すと、どちらでもない状態の閾値をもう1組決めることになり、
使われないまま保守対象になる。

0002 §2.6 が述べるとおり、GPU Mode は Workspace の概念であり
**coldaisle のデータモデルには現れない。** 本項は Workspace 側の設計にのみ効く。

### 2.2 `sys.gpu_state` の値は変えず、`mixed` の扱いを定める

0002 §2.6 が確定した5値と、それぞれが立つ条件は**変更しない**
（0002 は「既存値の意味変更・削除は不可」としている）。本記録が足すのは
**観測したときの扱い**だけである。

| 値 | 条件 | 扱い |
|---|---|---|
| `unknown` | NVML 利用不可 | 最も保守的な閾値セット |
| `idle` | CUDA プロセスなし | 通常 |
| `ai` | 推論サーバのプロセスのみ | 通常 |
| `compute` | 推論サーバ以外の CUDA プロセスが存在 | 通常 |
| `mixed` | 両方が存在 | **異常。切り替え失敗として警告する** |

### 2.3 `mixed` を値から削除しない

運用上起きない想定でも、**切り替えに失敗して両方動く状態は物理的にありえる。**
値を消すと、その状態は最も近い値（`compute`）に丸めて記録されることになり、
**閾値の選択を間違えたまま「正常」として記録が残る。**

観測できたものは観測できたとおりに記録し、扱いの側で異常と判定する。

### 2.4 検出したら「GPU モードの切り替えが失敗している」と警告する

対象は #36。閾値の切り替え（#18）とは別の警告として出す。

「熱くなった」ではなく「切り替えが失敗している」と出すこと。
前者だと利用者は冷却を疑い、原因（推論サーバが降りていない）に辿り着かない。

---

## 3. Consequences

### 良くなること

- 閾値セットが1組減る。Shared 用の閾値を実測（#19）で決める必要がなくなる
- 切り替え失敗が**無音の誤分類ではなく警告**として現れる
- Workspace 側の GPU Manager の状態遷移が単純になる（2状態）

### 悪くなること・その緩和

| トレードオフ | 緩和策 |
|---|---|
| 「AI を軽く動かしながら Compute」ができなくなる | もともと併用しない方針。必要になれば Mode を足す（値の追加は可） |
| `mixed` の警告が、意図的な一時併存でも鳴る | 警告のみでブロックしない（D-08）。切り替え中の短時間は継続時間の条件で吸収する（#36 で決める） |

---

## 4. 却下した代替案

| 案 | 却下理由 |
|---|---|
| `mixed` を値から削除する | 起きた状態が `compute` に丸められ、閾値の選択を間違えたまま記録が残る（2.3） |
| `mixed` を通常状態として扱い、最も保守的な閾値を当てる | 静かに間違った状態が続く。切り替え失敗は人が直す必要がある |
| Shared を残して使わない | 使われない閾値セットが保守対象として残る |
| 0002 §2.6 の表を書き換える | 決定記録は追記のみ。値と条件は変わっていないため、本記録で扱いだけを足す |
