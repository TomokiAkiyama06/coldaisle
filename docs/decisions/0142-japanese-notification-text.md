# 決定記録 0142: 通知の本文を日本語にし、最後の行に ID を残す

## 1. Context

Slack に届く通知の先頭の行は `🔴 [critical] RAPID_RISE [air.gpu_intake] — firing` の形で
（0135 §2.2）、重大度・ルール・メトリクス・状態がすべて英語の ID になっている。
所有者は「英語で読めない」とし、日本語にすることを選んだ（2026-10-15）。

所有者の選択:

- 日本語にし、**最後の行に ID を小さく残す**（例 `SENSOR_FAULT / air.room`）
- 重大度は critical=重大・warning=警告・info=情報。解除は `✅ [重大 解除] … — 解除`
- ルールの日本語の名前は `config/rules.yaml`、メトリクスは `config/metrics.yaml` の `label`
- 翻訳に LLM を使わない

0135 §2.2 は見出しの形を決めているため、置き換える記録が要る。

---

## 2. Decision

### 2.1 先頭の行の形

| 種別 | 先頭の行の形 | 例 |
|---|---|---|
| 発火 | `<記号> [<重大度>] <ルール名>（<メトリクス名>）— 発生` | `🔴 [重大] 温度の急上昇（GPU吸気）— 発生` |
| 解除 | `✅ [<重大度> 解除] <ルール名>（<メトリクス名>）— 解除` | `✅ [重大 解除] 温度の急上昇（GPU吸気）— 解除` |
| 発火の説明（#38） | `🔎 [<重大度>] <ルール名>（<メトリクス名>）の説明` | `🔎 [重大] 温度の急上昇（GPU吸気）の説明` |

- 記号（🔴 critical / 🟠 warning / 🔵 info / 解除は ✅）は 0135 §2.2 のまま
- 重大度の語: critical=`重大`・warning=`警告`・info=`情報`
- 状態の語: firing=`発生`・resolved=`解除`
- メトリクスを持たないアラート（`SENSOR_FAULT`・`PROBE_CHANGED`）は `（…）` を付けない
- 日次レポート（`📄`）と故障疑いの案件（`📄 エスカレーション候補 …`）の先頭の行は変えない（アラートではない。0135 §2.2 と同じ）

### 2.2 本文の行

```text
🔴 [重大] 温度の急上昇（GPU吸気）— 発生
値: 7.00 °C/分
7.00 ℃/分で上昇している
現在値: GPU吸気=41.80 °C, 室温=25.00 °C
http://127.0.0.1:8000/
RAPID_RISE / air.gpu_intake
```

1. 先頭の行（2.1）
2. `値:` — 発火の値と単位（2.4）。解除は値を持たないので出ない（今と同じ）
3. `detail` — ルールエンジンの文を**そのまま**（2.5）
4. `現在値:` — `<メトリクス名>=<値> <単位>` をメトリクスの ID の順に並べる（並びは今と同じ）。値が無いものは `—`
5. ダッシュボードの URL（今と同じ）
6. **最後の行に ID**: `<RULE_ID> / <metric>`。メトリクスを持たないアラートは `<RULE_ID>` だけ

説明（`🔎`）は先頭の行・説明の全文・URL・ID の行の順にする。説明の全文（検証済みの文と LLM の文）は変えない。

最後の行の ID は、ログ（構造化ログの `rule` / `metric`）・DB・`config/rules.yaml` と突き合わせるために残す。
Slack の書式（小さい文字）は使わない。宛先によらず同じ本文にするため（0013 §2.6）。

### 2.3 日本語の名前の置き場

- **ルール**: `config/rules.yaml` の各ルールの `label`（**必須**）。欠けている・空のルールがあれば
  設定の読み込みで `ValueError` にして起動しない（書き漏らしを ID のまま静かに通さない）
- **メトリクス**: `config/metrics.yaml` の `metrics` / `derived` の `label` と `unit`（既に必須）
- `config/metrics.yaml` に無いメトリクス（DB にだけある `gpu.1.core` など）は **ID のまま**表示し、単位を付けない

ルールの名前（初版。文言は所有者が `config/rules.yaml` で変えてよい。コードの変更は要らない）:

| ID | 名前 |
|---|---|
| `SENSOR_FAULT` | センサーの応答が途絶えた |
| `SENSOR_MISSING` | センサーの値が欠けている |
| `PROBE_CHANGED` | プローブが入れ替わった |
| `RECIRCULATION` | 排気の再循環 |
| `INTAKE_HIGH` | GPU吸気が高い |
| `AIRFLOW_DEGRADED` | 風量の低下 |
| `RAPID_RISE` | 温度の急上昇 |
| `ROOM_HIGH` | 室温が高い |
| `HUMIDITY_OUT_OF_RANGE` | 湿度が範囲の外 |
| `GPU_FAN_NOT_MANUAL` | GPU Fanを曲線のサービスが握っていない |
| `GPU_FAN_BELOW_CURVE` | GPU Fanが曲線より遅い |

### 2.4 単位の表記（表示の側だけで整える）

`config/metrics.yaml` の `unit` の値（API の `unit` が返す値）は**変えない**。人が読む本文でだけ次のように写す。

| `unit` | 表示 |
|---|---|
| `C` | `°C` |
| `flag` / `count` | 単位を付けない（数だけ） |
| それ以外（`%RH`・`%`・`W`・`GB`・`rpm`） | そのまま |

数と単位の間は半角の空白 1 つ（`24.10 °C`）。数の桁は今と同じ小数 2 桁。

`値:` の単位はルールの種類で決める（値の意味がルールごとに違うため。メトリクスの単位を機械的に付けると
`SENSOR_FAULT` の秒数に `°C` が付く）。

| ルールの種類 | `値:` の意味 | 表示 |
|---|---|---|
| しきい値・範囲・flag・高温と低回転（`recirculation` ほか・`humidity_out_of_range`・`gpu_fan_not_manual`・`gpu_fan_below_curve`） | メトリクスの値 | `7.20 °C`（メトリクスの単位を 2.4 の表で写す） |
| 変化率（`rapid_rise`） | 1 分あたりの変化 | `7.00 °C/分` |
| 無音（`sensor_fault`） | 届いていない秒数 | `31 秒` |
| 連続（`sensor_missing`） | ok でないサンプルの数 | `5 サンプル` |
| 出来事（`probe_changed`） | 値を持たない | 出ない |

種類はルールの型（`ThresholdRule` / `SlopeRule` …）から決める。ルールの名前（ID）で分岐しない。

### 2.5 `detail` の文は変えない

`detail` はルールエンジンが作り、DB（`alerts.detail`）に保存され、説明（#38）の材料になる。
本記録では変えない（文は既に日本語で、メトリクスの ID が混じるのは `GPU_FAN_*` と `PROBE_CHANGED` だけ）。

### 2.6 日次レポートの表も同じ名前にする

`## アラート` と `## 日の終わりに続いているアラート` の表のルールの列を `<ルール名>（<RULE_ID>）`、
重大度の列を 2.1 の語（`重大` / `警告` / `情報`）にする。測定値の表が既に `<表示名>（<メトリクス>）` の形なので揃える。
`coldaisle-report` に `--rules`（既定 `config/rules.yaml`）を足す。

LLM へ渡す版（`facts_markdown()`、0131 §2.4a）も同じ形で作る。除外の一覧のルールはその版に元から無いので、
その名前は LLM へ届かない。ルールの名前は設定の文字列で、時系列ではない（ルール 8 に当たらない）。

レポートの見出し（`# 日次レポート …`）と通知の先頭の行（`📄 日次レポート …`）は変えない。

### 2.7 変えないもの

- **故障疑いの案件資料**（`coldaisle-escalate`）とその通知の本文: 変えない（Claude・人が ID で突き合わせて読む資料。0131 §2.4a の除外もそのまま）
- **構造化ログの `rule` / `severity` / `metric`**: ID のまま（`text` だけが日本語になる）
- **連投の抑制・夜間の方針・宛先**（0013・0135 §2.1 / §2.3）: ID で判定するので変わらない
- **AI ツールの閾値（`describe_system` の `thresholds`）と運用メモリの事実**: `label` を含めない（閾値ではないため。LLM へ渡すものと `memory/` を変えない）
- API・ダッシュボードの表示

### 2.8 翻訳に LLM を使わない

名前は設定の辞書を引くだけで決まる（決定論的）。LLM が止まっていても、同じ入力からは同じ本文になる。

---

## 3. Consequences

### 良くなること

- 所有者が Slack の通知をそのまま読める
- 最後の行の ID でログ・DB・設定と突き合わせられる
- ルールの名前を変えるのに設定の変更だけで済む

### 悪くなること・その緩和

| トレードオフ | 緩和策 |
|---|---|
| 先頭の行に ID が無くなり、通知の一覧（Slack の検索）で ID を検索しにくい | 最後の行に ID がある（本文の検索で掛かる） |
| `config/rules.yaml` に `label` を足さないと起動しない（新しいルールを足すとき） | 起動時の検査で落ちる（2.3）。試験で全ルールに `label` があることを確かめる |
| 日次レポートの表が横に長くなる | 名前は短くする（2.3 の表） |

---

## 4. 却下した代替案

| 案 | 却下理由 |
|---|---|
| ID を先頭の行に残す（`🔴 [重大] 温度の急上昇 RAPID_RISE …`） | 所有者は最後の行を選んだ |
| ルールの名前をコードの辞書に置く | ルール 9（定数を設定へ）。所有者が名前を直すたびにコードの変更が要る |
| `label` を任意にし、無ければ ID | 書き漏らしが英語の通知として静かに通る |
| `config/metrics.yaml` の `unit` を `°C` に変える | API の `unit` が変わる（ダッシュボード・外部の読み手）。表示の側で写せば足りる |
| Slack の書式（`_…_` の斜体・小さい文字）で ID を小さくする | 宛先ごとに本文が変わる（0013 §2.6）。stdout に記号が混じる |
| LLM に訳させる | 所有者が否定。通知は LLM が止まっても届く必要がある |

## 5. 未決事項・仕様に無かった判断

1. **`値:` の単位をルールの種類で決めた**（2.4）。所有者の例は `SENSOR_FAULT` に `値: 24.10 °C` だったが、
   `SENSOR_FAULT` の値は届いていない秒数で、メトリクスを持たない。例は形の例として読み、意味の合う単位にした
2. **数の桁は今のまま小数 2 桁**にした（例の `55.0 %RH` は 1 桁）。メトリクスごとの桁は決めていない
3. **`detail` の文の中のメトリクスの ID は残した**（2.5）。日本語の名前へ写すかは、DB と説明への影響を見て別に決める
4. **説明（`🔎`）の先頭の行にメトリクスを足した**（0135 では無かった）。発火の通知と並べて読むため
5. **ダッシュボード・API のアラート一覧の表示**は変えていない。日本語にするなら別の Issue
6. 2.3 のルールの名前の文言は Claude の案。所有者が直してよい
