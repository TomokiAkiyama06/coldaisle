## 1. Context

0168 のボットは、許可したチャンネル**かつ**許可したユーザーの `app_mention` にだけ答える。所有者は Slack のスレッドで
「今のファンスピードは？」「温度は？」と続けて聞きたいが、2 つ目からもメンションを付けないと答えない（2026-11-23 の所有者の要望）。
また、質問ごとに独立して答えるので、「温度は？」が前の Fan の話の続きであることを踏まえられない。

## 2. Decision（所有者が §5 で選んだ案）

### 2.1 受け取る event

- `app_mention` に加えて、Socket Mode で `message` の event（`message.channels`、非公開のチャンネルなら `message.groups`）を受ける
- 答えるのは、**許可リストのチャンネル**（`COLDAISLE_SLACK_QA_CHANNELS`）**かつ許可リストのユーザー**（`COLDAISLE_SLACK_QA_USERS`）の、
  `subtype` の無い投稿だけ。メンションの有無は問わない。チャンネルの普通の投稿にも、スレッドの返信にも答える（§5 の 1）
- 答えないもの（0168 §2.2 と同じ）: 許可リストの外・ボット自身や他のボットの投稿（`bot_id` / `bot_profile`）・編集・削除・参加などの
  `subtype` のある投稿・DM・本文が空の投稿
- 1 つの投稿がメンションを含むと、Slack は `app_mention` と `message` の両方を送る。0168 §2.1 の (チャンネル, `ts`) の重複の判定で、
  1 回だけ答える
- 答えは今までどおり、その投稿のスレッド（スレッドの返信ならそのスレッド、普通の投稿ならその投稿を親にしたスレッド）へ返す
- Slack の App の設定を所有者が変える: **Bot Token Scopes** に `channels:history`（非公開のチャンネルなら `groups:history`）を足し、
  **Subscribe to bot events** に `message.channels`（同 `message.groups`）を足して Reinstall する。手順は `docs/ubuntu-deploy.md` 4.3 に書く

### 2.2 スレッドの直前のやり取り

- ボットは、答えたスレッドごとに、直前の **3 往復**（質問の文と、返した答えの文）を**プロセスのメモリ**に覚える（§5 の 3）
- 同じスレッドの次の質問では、system の指示の後・今の質問の前に、覚えたやり取りを user / assistant の発話として LLM へ渡す
- **期限は無い**（§5 の 2）。プロセスが再起動するまで覚える。覚えるスレッドの数は `slack_qa.max_threads`（256）までで、
  最も古く使ったスレッドから忘れる。数と往復の数は設定に置く（ルール 9）
- Slack の履歴（`conversations.replies`）は読まない。渡すのは、ボット自身が受けた質問の文と、返した答えの文だけ。
  答えの文はツールの集計値から作った文で、生の時系列ではない（ルール 8）
- 答えの数値の検査（0168 §2.3）は今のまま、**その質問で得たツールの結果**の数値だけを検証済みとする。前の答えの数値を
  繰り返した文には「未検証」の印が付きうる（数値はツールで取り直すよう system の指示に書く）
- 覚えたやり取りもログに出さない（0168 §2.5）

### 2.3 回数と費用

- 0168 §2.5 の上限（1 日 100 回・1 ユーザー 1 分 3 質問）はそのまま。メンションが要らなくなるので、許可したチャンネルでの発言は
  独り言も含めて質問として数える。上限に当たったら今までどおり「少し待ってください」と返すか、答えない
- 外へ送るものに、覚えた直前のやり取り（質問の文と答えの文）が加わる。どれも許可した人がそのスレッドで見たものである

### 2.4 試験（実機不要。ルール 7）

- 許可リストの `message` に答える・メンションなしでも答える・スレッドの返信は同じスレッドへ返す
- `subtype` のある投稿・ボットの投稿・許可リストの外・DM には答えない
- メンションを含む投稿に `app_mention` と `message` の両方が届いても 1 回だけ答える
- 同じスレッドの 2 つ目の質問で、1 つ目の質問と答えが発話として渡る。4 往復目で最も古い往復を忘れる。`max_threads` を超えると最も古いスレッドを忘れる
- 別のスレッドのやり取りは渡らない

## 3. Consequences

### 良くなること

- スレッドでメンションなしに続けて聞ける。前の話の続きとして答えられる

### 悪くなること・その緩和

| 悪くなること | 緩和 |
|---|---|
| 許可したチャンネルの独り言にも答え、LLM の呼び出しが増える | 許可リストのチャンネル**かつ**ユーザーに限る。専用のチャンネルで使う前提。0168 の 1 日・1 分の上限はそのまま |
| Bot に `channels:history` の scope が要り、許可リストの外の投稿も Slack からは届く | 届いても許可リストで捨て、本文をログに出さない。メモリに覚えるのは答えたスレッドだけ |
| 再起動で直前のやり取りを忘れる | 忘れても質問には答える（文脈が無いだけ）。Slack の履歴を読む経路を作らない |
| 前の答えの数値が「未検証」の印を受けうる | 数値はツールで取り直すよう指示する。印は誤りを隠さない方向の振る舞い |

## 4. 却下した代替案

| 案 | 却下の理由 |
|---|---|
| ボットが答えたスレッドの返信だけに答える | 所有者はチャンネルの投稿すべてに答える案を選んだ（§5 の 1） |
| Slack の履歴（`conversations.replies`）からやり取りを読む | 履歴の読み取りの scope と、ボット以外の発言を LLM へ送る経路が増える。ボット自身が受け返した文だけで足りる |
| 覚えたやり取りに期限を設ける | 所有者は期限なし（再起動まで）を選んだ（§5 の 2）。数の上限でメモリを抑える |
