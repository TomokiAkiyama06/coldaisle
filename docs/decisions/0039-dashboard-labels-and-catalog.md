## 1. Context

Issue #48 の残りは、MockSource の異常表示とデーモン停止時の見た目を
人間が目視で確かめる受入基準だった。その確認のためにオーナーが見たモック
（「#48 開発用ダッシュボード」）と、実装済みの画面とのあいだに差が3つあった。

1. **カード・凡例・センサー構成に内部のメトリクス名（`air.room`）が出ている。**
   表示名は `config/metrics.yaml` の `label` にあるが（決定記録 0009 §2.1）、
   API がそれを返していないため、画面は名前をそのまま出すしかなかった
2. **派生値に式が無い。** `d.intake_rise` と `1.45` だけでは、何から何を引いた値か読めない
3. **カードに「古い」のバッジが出る。** モックには無い

1 と 2 は API に表示名の出口が無いことが原因で、画面側だけでは直せない。
表示名を JavaScript に書き写すと `config/metrics.yaml` との二重管理になり、
0011 §2.6.1（**指標を増やすのは設定だけでできる**）が崩れる。

---

## 2. Decision

### 2.1 `GET /api/v1/metrics` を足す（読み取り専用・v1 への非破壊的な追加）

`config/metrics.yaml` の中身を返す。**値は返さない**（値は `/latest`）。

```json
{
  "metrics": {
    "air.room": {"unit": "C", "label": "室温"}
  },
  "derived": {
    "d.intake_rise": {
      "unit": "C", "label": "吸気上昇（再循環の指標）",
      "minuend": "air.front_intake", "subtrahend": "air.room"
    }
  }
}
```

- **DB を読まない。** 取り込みが止まっていても表示名は引ける
- 書き込み系は増えない（FR-307。既存のテストがそのまま効く）
- api-contract §6 の「新しいエンドポイントは v1 のまま追加してよい」に当たる。
  Workspace 側は使わなくてよい（知らないエンドポイントは影響しない）
- **Workspace 側の Issue は立てない**（2026-09-18、リポジトリ所有者が決定）。
  非破壊的な追加であり、Workspace の実装を変える必要が無いため

### 2.2 画面に内部のメトリクス名を出さない

カードの見出し・派生値・凡例・アラートの対象・センサー構成の「計測点」列は、
すべて `label` で出す。派生値のカードには式（`前面吸気 − 室温`）を添える。
値が `null`（入力のどちらかが `ok` でない。0009 §2.2）のときも式は出す。
**「—」だけだと、何が足りないのかを辿れない。**

表示名が引けないとき（起動直後に API が落ちていた、設定に無いメトリクス）だけ、
名前そのものに戻す。空欄より誤読が少ない。表は取れるまで定期更新のたびに取り直す。

センサー構成の「チャネル」列（`front_intake`）は残す。これはデバイスが送る名前で、
ROM と突き合わせる作業（`docs/calibration.md`）に要る。

現在値カードは `air.*` の7つに絞る（Issue の「7メトリクス」）。
`sys.*` は事象の回数で、現在値として並べるものではない。

### 2.3 `stale` のカードには文言のバッジを出さない ★0011 §2.4 の一部変更

`ok` / `missing` / `suspect` は従来どおり色と文言の両方で示す。
`stale` だけは**赤い左辺と値を薄くする**見た目にとどめ、文言は出さない。

根拠は、**`stale` のカードがあるときは画面全体の赤帯が必ず出ている**こと。
API の health は、周期メトリクスのどれか1つでも `stale` なら `stale` になる
（`_is_stale`）。赤帯（0011 §2.5）が「データが古い（最終受信から N 秒）」と
文で言っているところへ、7枚のカードに同じ「古い」を並べても読み手に何も足さない。

**色だけに頼ることにはならない。** 文言は赤帯が担う。
この前提（stale のカード ⇒ 赤帯）はテストで固定した。

### 2.4 アラート一覧を表にする

状態（発生中 / 判定中 / 解消）と重大度（情報 / 警告 / 重大）を列にし、
**文言でも出す**（0011 §2.4 と同じ理由）。対象のメトリクスは表示名で出す。

## 3. Consequences

### 良くなること

- 画面から内部名が消え、表示名を変えるのは設定だけで済む（0011 §2.6.1 を保つ）
- Workspace も同じ表で表示名を引ける（任意）
- 派生値が何を意味するかが画面だけで読める

### 悪くなること・その緩和

| トレードオフ | 緩和策 |
|---|---|
| API 契約にエンドポイントが1つ増える | 非破壊的な追加（api-contract §6）。読み取り専用で DB も読まない |
| `stale` のカード単体では文言が無い | 赤帯が必ず同時に出る。前提をテストで固定した（2.3） |
| 表示名が引けないと内部名に戻る | 定期更新のたびに取り直す。設定に無いメトリクスは空欄より名前のほうが読める |

---

## 4. 却下した代替案

| 案 | 却下理由 |
|---|---|
| 表示名を `app.js` に書き写す | `config/metrics.yaml` と二重管理になる。指標を足すのに JS の変更が要る（0011 §2.6.1 に反する） |
| `/latest` の各メトリクスに `label` を足す | 派生値は `dict[str, float \| null]` で、式を載せる場所が無い（形を変えると破壊的変更）。値の更新のたびに変わらない文字列を毎秒送ることにもなる |
| `config/metrics.yaml` を静的アセットとして配る | API を経由しない読み口が増える（#48 は「API経由化」）。YAML をブラウザで読む実装も要る |
| `stale` にも「古い」を残す | 赤帯と重複し、モックのレビューで外すことになった（2.3） |
| `stale` のカードに経過秒を出す | 赤帯が同じ秒数を出している。カードごとに違う秒数が出ると読み比べが要る |
