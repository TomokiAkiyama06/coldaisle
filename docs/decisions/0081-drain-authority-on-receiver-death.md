# 決定記録 0081: 受付スレッドの死を検知した tick で authority の枠だけを1回取り出す

- **種別**: Decision Record
- **Status**: FINAL（2026-09-30、リポジトリ所有者が承認）
- **Date**: 2026-09-30
- **Supersedes**: [0072](0072-control-admin-entry.md) §2.2 の「死んだあとは受け渡し口を読まない
  （受付スレッドの死後に残った指令も適用しない）」のうち、**authority の枠に残った降格のみ**。
  モードの枠を読まないこと、`MAX` を再起動まで保つこと、lease を付けないこと、0072 の他の節は有効
- **関連**: [0057](0057-authority-rollout-stage-changes.md) §2.6 /
  [0072](0072-control-admin-entry.md) §2.2 / §2.6 / §2.7 /
  [0076](0076-implementation-settled-points.md) §2.2（`admin_receiver_dead`）
- **対象 Issue**: #92

## 1. Context

0072 §2.2 は、受付スレッドが死んだら loop が自分で `MAX` に倒し、**死んだあとは受け渡し口を
読まない**と決めた。人の指令で冷却を弱める経路を、壊れた入口の後に残さないためである。

段階 2（#92）で authority の枠が加わった。`lower_authority` / `rollback_authority` は
安全側の指令として、監査を待たずに枠へ置き、クライアントに `pending` を返し、監査に
`accepted` を残す（0072 §2.7）。受付スレッドが「枠に置いた後、次の tick の前」に死ぬと、
0072 §2.2 のとおり枠を読まないので、この降格は memory にも journal にも入らない。
Fan は `MAX` のままだが、**再起動すると journal の高い stage で運転を再開する。**
受理した降格が黙って失われるのは、0072 §2.6 の「受理した降格は journal へ書き残す」と食い違う
（PR #192 の Codex レビューの P1）。

authority の降格は常に Learned の制御権を狭める向きで、冷却を弱める経路にならない。

## 2. Decision

1. 受付スレッドの死を**最初に検知した tick**で、loop は `MAX` への移行（0072 §2.2 の 1〜3）に加えて、
   **authority の枠だけを1回取り出す。** 取り出しは通常の tick と同じく非ブロッキング（lock を
   取れなければ取り出さない）
2. 取り出した降格は、通常の tick と同じ経路で `AuthorityRuntime` へ**無条件に**上限として入れ、
   heartbeat の後の書き残しで journal へ書く（0072 §2.6）。受付スレッドは死んでいるので、
   `applied` の結果を受付スレッドへ返しても応答には届かない。監査の `applied` は書かれないことがある
3. **モードの枠は読まない。** 死んだ後のモードは再起動まで `MAX`（0072 §2.2 のまま）
4. 2 tick 目以降は、これまでどおり受け渡し口を読まない
5. 取り出しの失敗（例外・lock を取れない）は error の構造化ログに残し、`MAX` への移行を妨げない
6. decision trace の `mode_command` の形は変えない（`admin_receiver_dead` は真、`command_id` は持たない。
   0076 §2.2）。取り出した降格は、その tick の `authority` の記録（`ControlTick` の `authority`）の
   `command_id` に残る

## 3. Consequences

- 良くなること: 受付スレッドの死の直前に受理した降格が、再起動で失われない
- 悪くなること: 死を検知した tick だけ、壊れた入口の枠を読む。緩和策: 読むのは降格の枠だけで、
  降格は安全側にしか効かない。取り出しは1回で、lock を待たない

## 4. 却下した代替案

- **0072 §2.2 のまま枠を読まない。** 受理した降格が再起動で失われ、人が送り直す必要がある。
  送った人は `pending` を受け取っているので、送り直しの必要に気づけない
- **死んだ後も毎 tick 枠を読む。** 死んだスレッドは新しい降格を置かないので、1回で足りる
