## 1. Context

2026-10-14 に 0121 の T3（データの遅れと復帰）を行った。`*_telemetry_stale` が上がるまでの時間は、T3-1 で 6000 ms、
T3-2 で 6000 ms、T3-2 のやり直しで 6001 ms だった。0121 の合格の条件は「5000 ms 以上・5000 ms + 1 tick 以内」なので、
6001 ms は形の上では 1 ms 超える。

コードを確かめて分かったこと:

- fand は sample の age を単調時計で数え、5000 ms を**超えたら** stale とする。tick は単調時計で 1000 ms ごとに来るので、
  最後の sample を初めて観測した tick から、stale はほぼ毎回ちょうど 6 tick 後に上がる。0121 の上限（6000 ms）は、
  この正しい動きの値そのものになっている
- 0121 が時間を測るのに使う trace の `ts_ms` は壁時計で、tick ごとに揺れる（T3 の trace の 244 の tick の間隔で、1000 ms から ±1 ms）。
  そのため、正しい動きでも 6000 ms の前後に散り、半分ほどの試行が形の上で不合格になりうる
- 本当の不具合（判定が 1 tick 早い・遅い）は ±1000 ms の差として現れる。数 ms の揺れとは桁が違う

また、T3 の「戻した後に温度と tach が落ち着く時間」は、試行の間ずっと別のプロセス（別のセッションのテスト。
CPU の約 40%・約 40 W）が動いていて、CPU の温度が試験の前から 45〜59 °C の間を揺れていた。
試験による変化と区別できず、CPU の温度では判定できなかった。

## 2. Decision

### 2.1 trace の壁時計で測る時間の条件に ±50 ms を許す

0121 の時間の条件のうち、trace の `ts_ms` 同士の差か、DB の行の時刻と trace の `ts_ms` の差で測るものは、
**下限・上限のそれぞれに ±50 ms を許す**。当てるのは次の条件:

- §2.5 T3: `cpu_telemetry_stale` / `gpu_telemetry_stale` まで、`air_telemetry_stale` まで（5000 ms 以上・6000 ms 以内 →
  4950 ms 以上・6050 ms 以内）、fault が消えるまで（30000 ms 以上・31000 ms 以内 → 29950 ms 以上・31050 ms 以内）
- §2.8 T6: stall の計時が始まった最初の tick から `tach_stall` まで（4950 ms 以上・6050 ms 以内）

fand が自分の単調時計で出した値があるときは、そちらで判定し、許容は掛けない。たとえば §2.4 T2 の「最初の失敗から
終了コード 7 まで」は、終了のログの `failing_ms` で判定する。

50 ms にする理由:

- 1 tick（1000 ms）の 1/20 で、1 tick の誤りを見逃さない
- `tick_deadline_ms`（250 ms）より小さく、tick の遅れも隠さない
- 観測した揺れ（±1 ms）に、NTP の slew や負荷の下の遅れの分まで十分な余裕がある

### 2.2 壁時計が飛んだ試行は使わない

許容は、壁時計が試行の間に飛んでいないことを前提にする。判定に使う2つの tick の `control tick` のログについて、
journal の `__MONOTONIC_TIMESTAMP` の差と、trace の `ts_ms` の差が 50 ms を超えて違うときは、その試行を使わずにやり直す
（0121 §2.3 が tick の間隔に壁時計を使わないのと同じ理由）。

### 2.3 T3 の落ち着きは、試験と無関係な CPU の負荷があるときは空気の温度と tach で判定する

試験の前から試験と無関係な CPU の負荷があり、CPU の温度がその負荷で揺れているときは、T3 の「戻した後に温度と tach が
落ち着く時間」を、空気の温度（`air.*`）と Front / Rear の tach で判定する。CPU の温度は値として記録し、合否に使わない。
負荷のプロセスと CPU Power を結果に残す（所有者の判断、2026-10-14）。

### 2.4 2026-10-14 の T3 の判定

§2.1〜§2.3 で、2026-10-14 の T3 は合格とする。値は `docs/fan-header-mapping.md`「0121 の試験の結果」に残す。

## 3. Consequences

### 良くなること

- 正しい動きの試行が、壁時計の数 ms の揺れで不合格にならない
- 1 tick の誤りは今までどおり捉える

### 悪くなること・その緩和

- 条件が 50 ms だけ緩む。1 tick（1000 ms）の誤りより十分小さく、値の確定に影響しない
- T3 の落ち着きを CPU の温度で見ていない。CPU の温度への fand の応答は T4（下げる速さ）と T7（BIOS との比較）で確かめる

## 4. 却下した代替案

| 案 | 却下の理由 |
|---|---|
| 条件はそのままで、6000 ms 以内に収まるまでやり直す | 揺れ次第で結果が変わり、判定の再現性が無い |
| 時刻ではなく tick の数で判定する（「初観測の tick から 5〜6 tick 後」） | 揺れの影響は無くなるが、書き換える条件が多い。許容を足すほうが、0121 の条件の形を保てる |
| 0121 を書き直す | 決定記録は書き換えない（追記のみ）。一部を置き換える新しい記録にする |
