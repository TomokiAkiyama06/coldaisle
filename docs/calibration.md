# センサー較正の手順（#13 / FR-107）

DS18B20 も AM2320 も確度は **±0.5℃**。最悪ケースで ΔT に **±1.0℃ の系統誤差**が
乗ります（`spec-review.md` W-02）。再循環の判定（`d.intake_rise > 5.0`）は
数℃の話なので、これは無視できません。

**改善するのはセンサー間の相対精度**です。絶対精度は変わりません。
本システムが判断に使うのは温度**差**なので、それで足ります。

---

## 1. 物理的な準備

ここが手順の本体です。**ソフトウェアは平均を取るだけ**なので、
置き方を間違えると「本物の温度勾配をオフセットとして焼き付ける」ことになります。

1. **全センサー（DS18B20 ×5 と AM2320）を1か所に集める**
   - プローブの先端どうしを 5cm 以内に寄せる
   - 束ねてもよいが、**互いに密着させない**（熱容量で追従が変わる）
2. **静止した空気の中に置く**
   - エアコンの吹き出し口、窓際、PC の排気の近くを避ける
   - サーバーは**止めておく**（動かすなら十分離す）
   - 人の出入りが少ない場所にする
3. **30分以上そのままにする**
   - プローブ自身の熱容量が周囲と釣り合うまで待ちます
   - **これを省くと、待ち時間の差がそのままオフセットになります**

## 2. 記録する

取り込みデーモンを動かしたまま、**10分以上**放置します。

```bash
uv run coldaisle-daemon --source serial
```

較正コマンドは**シリアルポートを開きません**（開いてよいのは取り込みデーモンだけ。
AGENTS.md ルール3）。保存済みのデータから計算します。

## 3. 計算する

```bash
uv run coldaisle-calibrate --minutes 10
```

```text
基準 24.001 C（mean_of_all）
ばらつき 0.501 C（上限 2.00）

  front_intake   平均   23.810 C  オフセット +0.191 C  (239 件)
  gpu_exhaust    平均   24.311 C  オフセット -0.310 C  (239 件)
  ...

書き込んでいません。内容を確認して `--apply` を付けてください。
```

**ここで止まります。** 較正値は以降のすべての測定の解釈を変えるので、
既定では書き込みません。

### 受け付けられない場合

| 表示 | 意味 | どうするか |
|---|---|---|
| ばらつきが上限（2.00℃）を超えている | **同じ空気に置かれていない** | 1 からやり直す。熱平衡の待ち時間を延ばす |
| 測定が少ないチャネルがある | 記録した時間が足りない | `--minutes` を延ばすか、もう少し待つ |
| 測定が無いチャネルがある | センサーが1本届いていない | 配線と `err` を確認する |

`--force` で押し切れますが**勧めません**。上限を超えたまま較正すると、
**本物の温度勾配が以降ずっと見えなくなります。**

## 4. 書き込んで再起動する

```bash
uv run coldaisle-calibrate --minutes 10 --apply
```

`config/calibration.json` が更新されます。**取り込みデーモンを再起動してください**
（較正値は起動時に読みます）。

```bash
# 何が変わったかを残す（#40）
uv run coldaisle-memory --apply --commit
```

## 5. 確かめる

較正後、**同じ状態のまま**もう一度測って、ばらつきが **±0.15℃ 以内**に
収まっていることを確認します（#13 の受入基準）。

```bash
uv run coldaisle-calibrate --minutes 10   # 書かずに見るだけ
```

`ばらつき` が 0.15 以下になっていれば完了です。

---

## やり直す時期

`config/calibration.json` の `revalidate_after_days`（既定 183 日 ≒ 6ヶ月）を
過ぎると、**取り込みデーモンが起動時に警告します。**

```json
{"level": "warning", "msg": "較正をやり直す時期（または未較正）", "age_days": 190.2}
```

次のときもやり直してください。

- **プローブを差し替えた**（`PROBE_CHANGED` が出たとき。FR-403）
- センサーを増やした・交換した
- 測定値が説明のつかないずれ方をしている

## 出荷時の状態

`config/calibration.json` は**全チャネル 0.0 / 未較正**で配布されています。
`calibrated_at` が `null` なので、デーモンは起動のたびに警告を出します。
**較正済みのつもりで生値を見ることにならない**ようにするためです。
