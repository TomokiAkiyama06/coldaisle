## 背景
**ローカルモデルに高価な機材の故障判断をさせてはいけない。**
構想メモ §10 の Escalation Policy を熱監視へ適用する。

| 分類 | 該当 |
|---|---|
| Qwen3.8-27B | 定型のアラート説明、日次レポート、履歴の問い合わせ、複数センサーの相関分析 |
| **Claude** | ハードウェア故障疑い、高額機材の保護判断、初見の異常パターン、RMA判断 |

## やること
- [ ] エスカレーション条件を**決定論的に**定義（例: `d.gpu_internal_delta` の段階的でない急変、
      ベースラインからの持続的逸脱、既知パターンにマッチしない critical アラート）
- [ ] 構想メモ §10 に倣い、**生の時系列ではなく圧縮した案件資料**を生成:
  問題 / 測定値 / 経過 / 試行済み / 争点
- [ ] 送信前に必ずユーザー確認を挟む（自動送信しない）
- [ ] Claudeの回答を Decision Memory へ記録

## 案件資料の例
```text
問題:
GPU hotspot が core より 22°C 高い状態が3日継続

測定値:
gpu.0.core     72°C (p95)
gpu.0.hotspot  94°C (p95)
air.gpu_intake 29°C（正常範囲）

経過:
2026-09-01まで差は12°C前後 → 2026-09-02から急に22°C前後へ

試行済み:
1. 吸気温は正常であることを確認
2. ファン回転数に変化なし
3. 負荷パターンに変化なし

争点:
サーマルパッド劣化か、センサー異常か、RMA相当か
```

## 受入基準
- エスカレーション判定にLLMを使わない（決定論的）
- 送信内容がユーザーに事前提示される
- Repository全体や生ログを送らない
