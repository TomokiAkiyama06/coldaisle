## 背景
**#24 を本Issueで置き換える。**

構想メモ §5.1/§8 の中核原則:
> モデルの「自信度」ではなく、何が検証済みで何が未検証なのかを管理する。

### 悪い出力（confidenceベース）
```text
排気の再循環が発生している可能性が高いです（確度: 87%）
```
87%に根拠はない。8Bモデルの自己申告は信用できない。

### 良い出力（Evidenceベース）
```text
RECIRCULATION 発火

VERIFIED（測定値）
✓ front_intake - room = 6.2°C が 8分間継続（閾値 5.0°C / 5分）
✓ room = 28.1°C（過去24hの中央値 26.4°C より +1.7°C）
✓ 全センサー quality = ok（センサー異常ではない）
✓ 同時刻に gpu.0.power = 580W

UNVERIFIED（未確認）
? 排気の再循環なのか、室温そのものの上昇なのか
? エアコンの稼働状態
? サーバー背面と壁の距離
? フロントフィルタの目詰まり

確認手順
1. サーバー背面と壁の間隔を確認（10cm以上あるか）
2. エアコンが動作しているか確認
3. フロントダストフィルタを確認
```

## やること
- [ ] VERIFIED / UNVERIFIED / 確認手順 の3ブロック構成で生成
- [ ] **VERIFIED に入れてよいのは測定値と閾値判定のみ**。推論を混ぜない
- [ ] **confidence / 確度 / 可能性が高い といった表現を禁止**するプロンプト制約
- [ ] Verification Level のマッピングを実装（L1=値の妥当性、L2=ルールエンジン、L3=LLM）
- [ ] 生成失敗時は素のアラートのみ通知（デグレード）
- [ ] 生成は通知経路をブロックしない（非同期・後追い）

## 受入基準
- 出力に確度の数値が一切含まれない
- VERIFIED の各行がDBの実データと照合できる
- AI生成が失敗しても通知は必ず届く
